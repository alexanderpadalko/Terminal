# FlowDesk — обязательные правила для Codex и ChatGPT

Этот файл действует для всего репозитория. Прочитайте его **до первого изменения файлов** вместе с `docs/CURRENT_STATE.md`, `docs/PROJECT_CONTEXT.md` и `FINAM_ONLY.md`.

## Единая версия и канал передачи

- Единственная активная ветка — **`main`**. Прежняя `codex/flowdesk-0.2.9-confirmed-bars` после миграции архивируется тегом и удаляется с remote. Остальные старые ветки — только архив; не продолжайте на них разработку.
- **Единственный источник истины — текущий `origin/main`**. Сообщение в чате, локальная копия и текст документа могут устареть; сверяйте `git log -1` и GitHub Actions.
- Пользователь поочерёдно работает в ChatGPT и локальном Codex. **Одновременно вносит изменения только один исполнитель**. До передачи работы: тесты, commit, push, обновление `docs/CURRENT_STATE.md`.
- Если есть незакоммиченная работа, не перезаписывайте её, не выполняйте `reset --hard`, `clean -fd`, force-push или rebase чужих коммитов без явного решения пользователя.
- Сначала проверьте `git status --short`, `git branch --show-current`, `git fetch origin`, `git log -1 --oneline origin/main`. Только при чистой папке: `git switch main`; `git pull --ff-only origin main`.
- После обновления основного кода со стороны ChatGPT локальный Codex должен выполнить fetch/pull перед новой правкой; ChatGPT обязан получать текущий HEAD GitHub перед записью. При конфликте остановиться и сопоставить обе версии, не удалять чужие правки.

## Бизнес-правила: не нарушать

- Текущая пользовательская версия **0.2.26**; **не повышать номер без решения пользователя**.
- В пользовательском списке разрешены только **8 указанных фьючерсов США, 20 акций РФ по последнему подтверждённому 20-сессионному рейтингу, 10 указанных фьючерсов РФ**. Не возвращать демо-акции США и ручное открытие невыбранных активов. Futures API symbols брать строго из активного каталога Finam `ticker@MIC`; не подменять ближайшими контрактами. При запуске обновлять топ-20 акций через MOEX ISS; показывать дату и кэш при ошибке. **Актуальное правило:** переключать фьючерс за один календарный день до проверенной экспирации (местная дата MIC) на следующую действующую серию той же биржи. **По обороту/объёму больше НЕ переключать.** Даты Finam GetAsset; для RTSX при отсутствии даты допускается MOEX LASTTRADEDATE. При неизвестной дате точный тикер из Finam остаётся доступен, но автопереход блокируется. Не терять подтверждённый roll state при сбое. Перпетуалы без ролловера. См. `docs/finam_watchlist.md`.
- **Резервный официальный календарь экспирации США:** если Finam GetAsset не вернул дату, разрешены read-only CME ProductCalendar/Future (NQ/ES/GC/SI/NG) и ICE Brent LTD (BRN@IFEU), только с точной валидацией серии и месяца. Невозможность прочесть источник = НЕТ даты, не вычислять её по коду месяца. Не использовать First Notice/опционные даты и не подменять истечение расчётной датой. В tooltip показывать только безопасный тип ошибки GetAsset или HTTP статус, не JWT/body. Для PL/PA/NG публичный продуктовый endpoint пока не подтверждён; не притворяться, что поддержка есть.
- **Только Finam Trade API** — поток, свечи и история графика. По прямому указанию пользователя MOEX ISS допустим ТОЛЬКО для служебной статистики: точный VALUE по TQBR за последние 20 завершённых сессий для топ-20, а также RFUD LASTTRADEDATE для проверки дат российских фьючерсов при отсутствии Finam-даты. Не включать MOEX как feed графика, не восстанавливать TRANSAQ.
- `Авто` включает Finam WebSocket; разрешение на рыночные HTTP/REST GET свечей — **только отдельной галочкой HTTP**. Служебные HTTPS-запросы Finam для получения и продления JWT разрешены независимо от неё.
- Токен Finam хранить только в безопасном локальном хранилище; никогда не помещать секреты, HTTP Authorization, bearer/JWT и ключи в коммиты, тестовые фикстуры, логи и отчёты. Не просить пользователя отправлять ключ в чат.
- **Никаких торговых поручений**: ни UI заявок, ни вызовов API для выставления, изменения или отмены ордеров.
- Эталон расчётов — TradingView **v2.11 H1 + H4**, исходный Pine SHA-256 `CC2E1422F6D865C7D4814B7FF7CD4EEA82F87EB89642E8EF5F158A47B85D057F`. Сохранить все 74 настройки, потоки №1–3, FVG, структуру, H1 на M1/M5, старшую ликвидность/IDM и сводку H1/H4/D/W/M.
- **Цена и подписи VWAP:** получать точность из Finam read-only asset metadata (`min_step / 10^decimals`); не округлять всё до 0,01 и не угадывать шаг по тикеру. Единый Decimal-формат с запятой для правой оси, last price, crosshair, OHLC и VWAP. На M1/M5 при включённом VWAP показывать текущий и при разрешённом `vwapShowPrevious` предыдущий VWAP на шкале; не рисовать отсутствующие значения. Не менять ни сами свечи, ни расчёт VWAP.
- Отображать **время начала исходной свечи**, не время доставки котировки; не подменять OHLC последней сделкой. Сохранить оптимизированные перекрестие, панорамирование, масштабирование, стабилизацию индикатора соединения и корректное закрытие Windows EXE.
- График Finam показывает время **биржи по MIC**, с автоматическим DST. Session VWAP US equities: **04:00–20:00 ET**, единая линия от премаркета через регулярную и постмаркет; сброс на следующей расширенной дневной сессии, не по Москве и не в 09:30/16:00 ET. Для неизвестного MIC не угадывать расписание. Другие якоря VWAP используют биржевой календарь.
- **Дополнительно для подтверждённых COMEX/NYMEX:** `GC/SI` на `XCEC` (или `XCME` по каталогу Финама) и `PL/PA/NG` на `XNYM` используют **Session VWAP 18:00–17:00 ET**, с перерывом **17:00–18:00 ET**, без сброса в 00:00 ET. Правило определяется по MIC **и** точному корню/серии фьючерса, не переносится на Brent/RTSX или другие коды без подтверждения. В TimeframeBar рамка фокуса не должна имитировать вторую выбранную кнопку — подсветка только для `:checked`.
- **Только для NQ/ES CME Globex на XCME:** Session VWAP сбрасывается в **18:00 ET / 17:00 CT**, торговая сессия включает 18:00 ET → 17:00 ET следующего дня (17:00–18:00 ET перерыв); через полночь не сбрасывать. Sunday 18:00 ET начинает Monday trading date. Автоматически учитывать DST через IANA. Шкала графика продолжает показывать Chicago CST/CDT, а не принудительно Нью-Йорк. Другие срочные инструменты, другие якоря VWAP, акции US 04:00–20:00 ET — без изменений. См. `docs/exchange_time_vwap.md`.
- Не переносить автоматически расписание MOEX на Finam/NYSE/NASDAQ. Право на реальные данные, задержка, состав OHLC и паритет с TradingView устанавливаются только подтверждёнными проверками.

## Политика диагностик (13.11.2026)

- На акциях MOEX `MISX` (`XMOE`) с 23.03.2026 аукцион закрытия 18:55–19:00 МСК: M1 18:55–18:59 и M5 18:55 должны удаляться из **расчётного** intraday series до анализа, но сырая Finam SQLite история сохраняется. Нельзя вырезать этот бар у фьючерсов/других MIC. H1/H4/D/W/M OHLC нельзя молча переписывать без полного подтверждённого минутного источника; не заявлять, что эти старшие периоды полностью очищены.
- При смене **символа** Finam-only окна сбрасывать прежний ручной price_range и time viewport до открытия нового, чтобы масштаб сразу соответствовал котировкам нового инструмента; при обновлении того же инструмента цена не должна возвращаться к автонасройкам.
- Структурная ломаная (подтверждённые и формирующиеся плечи) всегда рисуется **после свечей**, поверх тел/фитилей, в обеих темах. Не менять алгоритм расчёта, только порядок QPainter.

- Ценовая и временная шкалы должны повторять эффект из видео от 13.11.2026: при изменении масштаба и размеров графика шаг округлённых делений автоматически меняется, подписи появляются/исчезают без перекрытий. **Не возвращать фиксированные 7 значений**. Price ticks учитывать фактическую точность Finam и форматирование `format_price`; time ticks строить по реальным биржевым timestamp свечей через `ExchangeClock.local` с DST и без вымышленных свечей в перерывах. Алгоритмы в `flowdesk/chart_axes.py`, не влияют на OHLC, VWAP, FVG, структуру и код ролловера.

- В `SettingsDialog(finam_only=True)` не возвращать неработающую галочку «Показывать боковую панель» и информационную надпись «Время свечи — время её начала…»; справа в FinamWindow всегда есть работающий список инструментов. При редактировании Finam-настроек сохранять историческое `ApplicationSettings.show_panel` без изменения, поскольку старый `MainWindow` по-прежнему использует его для своей панели. Интервал резервного HTTP и кнопку изменения токена на вкладке «Приложение» оставить.

- Цена на шкале обязана иметь контрастный (белый/чёрный) текст относительно *итоговой* заливки плашки; нельзя использовать фиксированный тёмный текст на чёрных свечах. Горизонтальная линия последней цены рисуется внутри plot до плашек, без пересчёта цен и с резервным контрастным цветом, если тон плашки не виден на фоне.
- У VWAP предыдущей сессии в ценовом теге — **только числовое значение**, у текущего остаётся надпись `VWAP`. Внутренние идентификаторы уровней и расстояния между тегами не ломать. Подписи FVG должны иметь RGB соответствующей зоны и альфу=255, не наследовать прозрачность заливки, в обеих темах.
- Поле процентов прозрачности должно отображать `100%` целиком, не обрезаться кнопками spin. Сохранять 0–100% и преобразование в `#RRGGBBAA`.

- Пользовательские «Показывать состояние инициализации» и «Диагностика FVG H1 / M1 / M5» не возвращать. Их `showMarketStatusInput` и `fvgMtfDiagnostics` всегда `False`, даже если старый сохранённый JSON содержал `True`. Не удалять эти поля из закреплённого 74-польного manifest/формата без отдельного плана миграции. Это не отменяет основной расчёт FVG.
- В первой вкладке графика настраивается цвет текста шкалы (`chart_axis_text`) и сохраняется в `ApplicationSettings`. Цветовая палитра — фиксированная 10×8 по образцу от 13.11.2026; выбранный цвет должен иметь явно видимую рамку (произвольный выделяется через «+»), выбранная прозрачность сохраняется.

- «Пустые внутренние свечи» (`ibEnabled`) обязаны давать прозрачные тела с контуром в **обеих** темах (в том числе тёмном FinamWindow). Использовать только исходный `inside_mother_bars` high/low, не мутировать OHLC и расчёты.
- Первая вкладка настроек — «Настройки графика», с цветами up/down body, up/down border, up/down wicks, background и grid. Применять к обеим темам графика, хранить восемь дополнительных необязательных полей `chart_*` только в `ApplicationSettings`; старые файлы без этих полей не должны менять внешность. Цвет в `#RRGGBBAA`; не включать эти параметры в 74 PIN-описания Pine и контрольные суммы.

- В пользовательских настройках FlowDesk не показывать надпись об эталоне и имя TradingView (источник версии и SHA оставлять только в коде/документации). Не показывать переключатель `showDevelopingLeg` — он всегда включён, в том числе при открытии старых настроек. Сохранять 74 внутренних параметра для совместимости.
- Выбор цветов — компактная сетка оттенков, собственный цвет и прозрачность 0–100%, без обязательного системного QColorDialog. В сохранении по-прежнему строго `#RRGGBBAA`, где прозрачность Trading-style 0% соответствует `FF`, 100% — `00`. Не изменять реальные цвета и их альфа-канал при чтении старых настроек.

- FinamWindow должен оставаться минимальным: не добавлять нижнюю подсказку жестов, строку числа свечей/исторического предупреждения или панель «Авто / HTTP / Последние / Автоцена / Токен Finam». Клавиши `End` и `F` сохраняются. В FinamWindow WebSocket и HTTP-история всегда включены, даже если старые настройки выключали их. Токен Finam вводится только в шестерёнке ⚙ → вкладка «Приложение» и хранится в системном хранилище. При смене токена сбросить прежнюю авторизацию и account-scoped cache. Не изменять общие настройки для исторического MainWindow, если этого явно не попросили.

- В пользовательском терминале **не добавлять диагностические кнопки, окна или технические футеры**. Не показывать строку времени наблюдения/разрешённой задержки и детальные статусы источников под списком инструментов. Не удалять саму логику проверок.
- Служебные результаты экспирации, ошибок Finam/бирж и рыночных срезов — только в локальном вращающемся `~/.flowdesk/logs/diagnostics.log`. Только заранее утверждённые технические коды, точные символы и даты, но **никогда** не копировать в лог тело ответа API, текст исключения, URL, JWT, account_id, секреты. Лог не отправляется автоматически, остаётся на компьютере пользователя. При неподтверждённой экспирации автопереход остаётся запрещён.
- В интерфейсе могут оставаться обычные сообщения о невозможности открытия инструмента, но не панель подробной диагностики.

## Готовность задачи / передача работы

1. До изменения прочитать текущее состояние; установить действующий HEAD, рабочее дерево и исходную ветку.
2. Выполнить точечные изменения, не переписывать код, не относящийся к задаче. Сохранить текущий UI, настройки и вычисления.
3. Запустить релевантные тесты; перед выпуском — Windows GitHub Actions (включая упаковку EXE и тест закрытия). Не называть тестовые данные доказательством живых котировок.
4. В том же PR/коммите обновить `docs/CURRENT_STATE.md`: что сделано, что не проверено, какие тесты, известные проблемы и следующее действие. `docs/CHANGELOG.md` обновлять при содержательных функциональных изменениях, а не после каждого технического коммита.
5. Commit + push; проверить, что удалённый HEAD содержит коммит. Только после этого передать управление другому инструменту, указав ссылку на коммит и CI.
6. В идеале вести небольшую задачу в отдельной краткоживущей ветке от `main`, сливать через PR после CI и удалять ветку. Для точечных правок по договорённости допускается запись сразу в `main`, но не поверх изменённой удалённой ветки.
7. Не добавлять устаревшие бинарные файлы, ZIP или дубли исходников в Git. Готовые EXE публикуются как GitHub Actions artifacts.

## Windows code signing

- Никогда не маркировать ZIP/EXE как `SIGNED` без успешной Windows Authenticode и RFC3161 timestamp-проверки.
- Настройка OIDC Microsoft Artifact Signing выполняется только владельцем проверенного издателя; подписывать лишь на `main`. Пока настройки отсутствуют — только явный `UNSIGNED` artifact.
- Запрещено коммитить закрытый ключ, PFX, пароль, Finam secret и другие учётные данные. Не отключать SmartScreen в качестве решения. Подробности: `docs/CODE_SIGNING.md`.

Если описание текущего состояния расходится с GitHub, доверяйте проверенному новому коду/CI и **обновите документ**, не угадывайте. Больше деталей — `docs/PROJECT_CONTEXT.md`.
