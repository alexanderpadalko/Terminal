# Исправление таблицы H1 в TradingView v2.11

Файл `TradingView_v2.11_H1_table_fix.pine` — отдельная модифицированная копия эталонного скрипта v2.11, **не замена эталона** `TradingView_v2.11.pine`.

На H4/D/W/M таблица получает H1 через `request.security(..., "60", f_mtfBundle(), lookahead_off)`. Ранее `f_flowSnapshot` отдавал снимки лишь на `barstate.islast` и `barstate.islastconfirmedhistory`. Поскольку `request.security` возвращает один из часовых баров внутри старшей свечи, он мог выбрать бар с `na` и показать прочерк вместо уже рассчитанного H1.

В модификации снимок H1 публикуется на каждом часовом баре **только при запросе со старшего графика**. Подтверждение по `closedAt` через `f_mtfConfirmed` остаётся неизменным, так что незакрытая H1-свеча не должна менять подтверждённое направление. Для случая действительного отсутствия данных добавлено различение сообщений в подсказке таблицы.

**Проверка на TradingView:** выбрать H4, D, W и M, сравнить направление H1 с отдельно открытым часовым графиком того же инструмента на одинаковом времени; проверить открытые свечи и Bar Replay. Исходник не компилировался в редакторе TradingView при подготовке этой правки.

В FlowDesk 0.2.26 поправлен `flowdesk/pipeline.py`: H1 включается в расчёт `summary_sources` для H4/D/W/M при наличии часовых данных. Это не подставляет направление H4 вместо H1 и не меняет расчёт индикатора.
