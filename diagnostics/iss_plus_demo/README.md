# Отдельная диагностика MOEX ISS+ DEMO

Скрипт не импортирует и не изменяет терминал, индикатор, кеш котировок или настройки приложения. Используется только общедоступная пара DEMO/guest; ключи аккаунтов не запрашиваются.

Запуск из каталога скрипта:

```powershell
python -m pip install websockets==15.0.1 tzdata==2026.4
python probe.py --self-test
python -u probe.py --mode full --out evidence
```

Полный тест занимает около восьми минут при успешных подписках. Проверяются подключение/STOMP CONNECTED, securities (цены и торговый статус), candles на документированных интервалах и отдельно M5/H4, orderbooks и пробная недокументированная подписка trades. Пустая подписка, ERROR, разрыв соединения и отсутствие доступа записываются раздельно. Короткий тест: `--mode smoke`; проверка окружения без установленного websockets: `--mode environment`.

`summary.json` содержит статистику, ошибки, образцы данных, HTTP-контроль и измерения возраста меток. `frames.ndjson` — все отправленные команды и полученные STOMP-фреймы с UTC-временем и монотонным таймером. Во время наблюдения за подпиской HTTP-запросы не выполняются; служебные heartbeat/ping продолжаются. Фактический возраст `TIME`/`TILL` вычисляется отдельно от возраста `SYSTIME`, а исторический снимок отделяется от последующих updates.

HTTP Date служит приближённой поправкой часов, не независимым эталоном биржевого времени. Возраст последней сделки включает задержку канала, пакетирование, неактивность торгов и сеть. Для времён без даты день восстанавливается как ближайший к приёму. Нельзя считать одно сообщение или RECEIPT доказательством устойчивого потока; в отчёте есть число сообщений и длительность наблюдения.

Тест разрыва намеренно обрывает клиентский TCP-транспорт. Затем открывает новое соединение и явно повторяет подписку. Это проверка восстановления клиентом, а не обещание серверного хранения подписок или автоматического восполнения пропущенных свечей.
