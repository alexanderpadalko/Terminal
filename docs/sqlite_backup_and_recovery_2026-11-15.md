# FlowDesk: безопасность SQLite, резервные копии и восстановление

Версия: 0.2.26. Реализация: `flowdesk/storage_safety.py`, `flowdesk/market_services.py`, `tools/flowdesk_storage.py`.

## Что происходит автоматически

- После запуска терминала, затем примерно каждый час, проверяется наличие **проверенной копии за текущие сутки UTC**. Копирование выполняется в фоне; с 06:00 МСК ежедневное обновление списков это не связано.
- Только существующие базы с ненулевым числом свечей копируются. База Binance создаётся лишь при первом выборе криптоинструмента; после первой загрузки также планируется проверка копии.
- Используется `sqlite3.Connection.backup`, **не простое копирование .sqlite3**. Поэтому сохраняются транзакции, которые находятся в WAL. Источник дополнительно проходит `PRAGMA integrity_check`; скопированная база также полностью проверяется.
- Новая копия сначала пишется в отдельный временный файл, и только после успеха публикуется целым файлом. При повреждении базы или сбое записи существующие копии **не удаляются**.
- Хранится **до трёх последних дневных копий на базу**. Папки:
  - `%USERPROFILE%\.flowdesk\backups\finam_candles_v1\`
  - `%USERPROFILE%\.flowdesk\backups\binance_candles_v1\`
- Копии хранятся **на том же диске**; они защищают от части логических повреждений, но **не заменяют** резервирование на другой диск.
- Если файл настроек повреждён, перед следующей записью он сохраняется как `settings_v211.json.invalid-...`, а не уничтожается молча.
- При повреждённой основной базе Finam программа не создаёт пустую новую вместо пользовательской: показывает предупреждение и число сохранённых копий, оставляя исходник нетронутым.

## Проверка и восстановление из Python

В корне исходного репозитория, с установленными зависимостями:

```powershell
$database = "$env:USERPROFILE\.flowdesk\finam_candles_v1.sqlite3"
python -m tools.flowdesk_storage --database $database --verify
python -m tools.flowdesk_storage --database $database --list
python -m tools.flowdesk_storage --database $database --backup
```

Восстановление выполняется **только в новый файл** (если файл уже существует, программа выдаёт ошибку и не перезаписывает его):

```powershell
$backup = "$env:USERPROFILE\.flowdesk\backups\finam_candles_v1\20261115T120000Z_0123456789ab.sqlite3"
$newfile = "$env:USERPROFILE\.flowdesk\finam_candles_v1.recovered.sqlite3"
python -m tools.flowdesk_storage --database $database --restore $backup --output $newfile
python -m tools.flowdesk_storage --database $newfile --verify
```

Путь копии выше — **пример**, не реально созданный файл. Выберите фактический путь из `--list`.

После восстановления **полностью закройте FlowDesk**. Перед любым ручным переключением базы переместите **исходные** `.sqlite3`, `.sqlite3-wal` и `.sqlite3-shm` в отдельную папку для сохранения доказательств. Только затем переместите `*.recovered.sqlite3` на штатное имя базы. Нельзя оставлять старые WAL/SHM рядом с новой базой: они относятся к исходному файлу. Пользовательский токен Finam не требуется для восстановления копии.

Для Binance замените имя файла на `binance_candles_v1.sqlite3`.

## Что пока не гарантируется

- Проверка не моделирует реальный сбой питания и поведение диска при аппаратном отказе.
- Копирование в памяти фонового потока не может быть гарантированно закончено при немедленном выключении Windows: временные файлы не считаются готовыми копиями.
- Автоматическое переключение на более старую базу **специально не реализовано**: оно может потерять свежую историю и скрыть повреждение исходного файла. Восстановление требует явного решения пользователя.
- Эти средства сохраняют целостность локальных файлов; они не проверяют подлинность/полноту исторических данных Finam/Binance и не являются автоматическим gap detector.
