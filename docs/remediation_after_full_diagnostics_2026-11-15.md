# FlowDesk 0.2.26 — устранение замечаний без длительных испытаний

Дата: 15 ноября 2026. **Последний проверенный код:** [301f6d1f14c94566aacaf49fdd2bff861b87ee25](https://github.com/alexanderpadalko/Terminal/commit/301f6d1f14c94566aacaf49fdd2bff861b87ee25).
Последующий коммит `196f881` только группирует Dependabot PR, не меняет приложение или EXE.

## Реализовано

1. **Автоматические SQLite-снимки Finam и Binance.** В фоне после запуска, затем с часовым интервалом; не более одного снимка на базу за UTC-день. Binance проверяется также после первой загрузки. Хранится три последних датированных снимка в `%USERPROFILE%\.flowdesk\backups\<имя базы>\`. При пустой базе снимок не создаётся. Используется SQLite online backup, учитывающий незавершённый checkpoint WAL.
2. **Проверка целостности перед публикацией.** Исходная и скопированная SQLite проходят `PRAGMA integrity_check`; копия сначала создаётся во временном файле, а затем атомарно публикуется. Старые успешные копии сохраняются при ошибке; удаляются только старые файлы снимков по строгому шаблону, после успеха.
3. **Недеструктивное восстановление и проверка.** `tools/flowdesk_storage.py` предоставляет `--list`, `--verify`, `--backup`, `--restore SNAPSHOT --output NEWFILE`. Восстановление создаёт исключительно **новый** файл через эксклюзивную файловую ссылку, отказавшись перезаписывать существующий. Переключение на восстановленную базу — сознательное ручное действие при закрытом приложении; старые WAL/SHM должны быть убраны в карантин вместе с повреждённой базой.
4. **Понятные сбои вместо тихого сброса базы.** Finam SQLite с повреждённой схемой/заголовком вызывает предупреждение при старте, а ошибка лениво открываемой Binance SQLite — понятный статус без исключения в Qt slot. Ни один из вариантов не затирает пользовательскую историю.
5. **Сохранение повреждённых настроек.** Если `settings_v211.json` ранее не удалось прочитать, при следующей записи оригинал сохраняется в отдельном `.invalid-...` файле, после чего новая конфигурация записывается атомарно в собственный временный файл.
6. **Короткие проверки DPI без физического монитора.** Запуск отдельных Qt offscreen-процессов при `QT_SCALE_FACTOR=1 / 1.25 / 1.5 / 2`. Проверены три FVG-палитры по 80 swatch и 90px контролы прозрачности. Это виртуальное масштабирование, не ручной тест видеодрайвера.
7. **Наблюдение за уязвимостями зависимостей.** Добавлен `pip-audit` в Windows CI, JSON сохраняется как evidence, и сгруппированные еженедельные Dependabot PR для pip/GitHub Actions (без автоматического merge). Проверка уязвимостей не блокирует сборку, но её итог оценивается отдельно.

## Что не заменяется этой проверкой

- 24–72 ч реального WebSocket/HTTP с пользовательским токеном и измерение RAM/CPU/latency под непрерывным потоком.
- Независимый candle-by-candle parity сигналов с TradingView на одинаковых входах и полнота многолетних исторических данных, включая дырявые диапазоны.
- Подтверждение полевых DPI/графических драйверов и реального отключения питания при транзакции.
- Защита от отказа всего диска (резервные копии хранятся в профиле на том же диске), цифровая подпись **UNSIGNED** и воспроизводимые публичные релизы.

**Ограничение:** восстановление не переключает повреждённую БД на копию автоматически — это намеренно, чтобы не терять более свежую информацию и не скрывать исходную ошибку. Подробная инструкция: [sqlite_backup_and_recovery_2026-11-15.md](sqlite_backup_and_recovery_2026-11-15.md).

**В рамках этой работы расчёт сигналов, структура FVG/потоки, v2.11 и перечень инструментов не изменялись.**
