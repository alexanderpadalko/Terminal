## Актуальная версия

### NQ / ES — границы Session VWAP CME Globex (13.11.2026)

- **Для контрактов `NQ...` и `ES...` на `XCME`:** сессионный VWAP начинается **в 18:00 ET** (17:00 CT) и продолжается до **17:00 ET следующего дня**; пауза **17:00–18:00 ET** исключается из расчёта. Новая биржевая дата присваивается бару 18:00. Переход через 00:00 ET/МСК/CT не сбрасывает линию. В воскресенье с 18:00 ET открывается сессия понедельника, в пятницу с 17:00 ET — закрытие на выходные.
- **Отбор по инструменту, не только MIC:** `NQZ6@XCME`/`ESZ6@XCME` и варианты года распознаются автоматически, `GC`/`SI`/`NG` и другие фьючерсы не затрагиваются. UI по-прежнему показывает **время биржи Chicago CST/CDT**, а граница VWAP определяется **America/New_York EST/EDT**, обе зоны IANA с DST.
- **Неизменность данных:** свечи, UTC-время в Finam/SQLite, биржевые OHLC, другие VWAP anchors, настройки TradingView v2.11 и HTTP-policy не меняются. Отсутствующие свечи не создаются; сброс начинается с первого доступного бара новой сессии.
- **Контроль:** тесты в `tests/test_cme_session_vwap.py` покрывают 16:55/17:00/17:59/18:00 ET, ночной переход, выходные, DST, смену инструмента и VWAP в Qt. Проверка с реальным потоком Finam и праздничные/сокращённые сессии CME ещё открыты.
- Источник расписания: https://www.cmegroup.com/markets/equities/sp-500-and-nasdaq-100-futures.html ; подробности `docs/exchange_time_vwap.md`.

### Список инструментов по изображениям — 13.11.2026

- Пользователь закрепил **ровно 3 группы** в Finam GUI: **8 US futures** (`NQZ2026, ESZ2026, GCZ2026, SIZ2026, PLF2027, PAZ2026, NGZ2026, BRNF2027`), **20 российских акций по обороту**, **10 российских futures** (`SIZ2026, CRZ2026, EUZ2026, EDZ2026, USDRUB.P, CNYRUB.P, EURRUB.P, MIXZ2026, RIZ2026, IRUS.P`).
- В UI не показывать Apple/Tesla и остальные демонстрационные активы, а также ручной выбор произвольных инструментов. Поиск — только по этим 38 строкам.
- **Биржевое время фьючерсов:** RTSX → Europe/Moscow, XCME → America/Chicago, XCEC/XNYM → America/New_York, IFEU → Europe/London; UTC-метки свечей не меняются. Границы сессий VWAP срочных контрактов ещё требуют расписания каждого инструмента, не применять 04:00–20:00 ET акций к фьючерсам. Для REST и WebSocket сохранять точный регистр API-тикера из справочника (например, `SiZ6`).
- **Фьючерсы:** метки пользователя не являются подтверждёнными API-символами. Подключать только при точном соответствии `ticker@MIC` в активном справочнике Finam `GET /v1/assets/all`. Для RTSX/MOEX и CME/COMEX/NYMEX/ICE используются разные MIC. Недоступный/неоднозначный контракт остаётся видимым, но **не подменяется и не открывается**.
- **Топ-20 акций:** используем первые 20 из сохранённого и ранее проверенного 20-сессионного ранжирования `watchlist_v1.json`, либо 20 из исходного seed с **явной меткой исходного (не подтверждённого) списка**. Дата сохранённой выборки отображается. Устаревший рейтинг **пока не пересчитывается автоматически**: Finam REST не даёт в текущем API готовой исторической таблицы рублёвого оборота всех акций за 20 завершённых сессий; подменять её расчётом `цена×объём` или оборотом одного дня нельзя. Не использовать MOEX HTTP тайно: основной терминал остаётся Finam-only.
- **Проверка:** каталог Finam и права пользователя проверяются только при локальном ключе на компьютере пользователя; серверная CI работает на моках. URL: `docs/finam_watchlist.md`.

### Время биржи и VWAP расширенной сессии — исправление 13.11.2026

- Для Finam выбирается **биржевой IANA-часовой пояс по MIC**: XNGS/XNYS/ARCX и другие американские equity MIC → `America/New_York` (EST/EDT с автоматическим DST), MISX → `Europe/Moscow`. Для неизвестных MIC явно используется UTC без угадывания местной зоны.
- Нижняя ось, время под перекрестием, заголовок OHLC и временные сообщения Finam показывают **биржевое время**; исходные UTC-метки свечей, OHLCV и SQLite не меняются.
- **Session VWAP американских акций включает премаркет, основную сессию и постмаркет в одном расчёте с 04:00 до 20:00 ET**. Сброс с первым доступным баром новой дневной сессии, не в 09:30 ET, не в 16:00 ET и не в полночь Москвы. Интервал 20:00–04:00 ET не включён без отдельного решения о ночной сессии. Week/Month/другие календарные якоря используют календарь биржи.
- Новые регрессии проверяют DST, 04:00 ET, 09:30 ET, 16:00 ET (= 00:00 МСК зимой), 20:00 ET, переход следующего дня и синхронизацию Chart/VWAP при смене MIC.
- **Статус:** **Windows CI 43401824324 успешно завершён** для кода `3453c176e856d69d8d2fb037ca99176747fdb519`: 363 теста, собран EXE, проверено закрытие и Finam executor/DNS. Синтетические тесты включают 04:00, 09:30, 16:00, 20:00 ET и DST. Подтверждение реальной истории премаркета/постмаркета Finam и паритета с TradingView ещё требуется.
- Подробное описание: `docs/exchange_time_vwap.md`.

## Текущие функциональные договорённости

| Область | Решение |
| --- | --- |
| Данные | **Только Finam Trade API**; без активного MOEX ISS+ DEMO или TRANSAQ |
| Авторизация | Режим «Просмотр»; локальный secret key → временный JWT; без торговых операций |
| Поток | `wss://api.finam.ru/ws` для котировок/свечей; `Авто` включает поток |
| HTTP | Включается отдельной галочкой только для рыночной REST-истории/восстановления; запросы авторизации разрешены всегда |
| Символ | `тикер@MIC` (SBER@MISX, AAPL/TSLA@XNGS, IBM@XNYS — MIC из справочника, не гарантия доступа) |
| Свечи | M1, M5, H1, H4, D1, W1, MN1; время начала свечи исходное; сохранять отдельно в `~/.flowdesk/finam_candles_v1.sqlite3` |
| Анализ | Структурная ломаная, BOS/CHOCH/MAX/MIN, IDM, потоки №1–3, H1-проекция на M1/M5, FVG и VWAP по v2.11 |
| Интерфейс | Полный логотип FD/FLOWDESK, плавный график, 7 ТФ, правый выбор инструмента, тёмное оформление |

## Что подтверждено

- Текущая база Finam проходит **363 автоматических теста** на Windows, включая адаптеры с имитированными ответами, новую сессионную логику VWAP/DST, регрессии старого движка, открытие GUI без токена и корректный выход из упакованного EXE.
- Правила хранения секретов, привязки HTTP-политики и отдельного SQLite предусмотрены в коде.
- Исправления ускорения графика, расчётов и Windows-активации/закрытия перенесены через историю ветки до Finam.
- **Подтверждены живым Finam-токеном после базы 346 тестов:** история H1 и потоковые снимки TSLA@XNGS по всем семи ТФ, как описано выше. **Не подтверждены:** фактическая задержка, длительная доставка новых свечей, полнота истории, биржевые сессии США и полный паритет TradingView. Успешная сборка EXE этого не доказывает.
- Поддержка сохранённой MOEX-диагностики **не означает**, что MOEX остаётся текущим поставщиком.

## Открытые технические задачи

1. **Живая проверка подключения к Finam на компьютере пользователя** без передачи ключа в чат: JWT, подписки, права MIC, timestamp последней сделки и свечей, ошибки, возможное ограничение каналов.
2. **Проверить длительный Finam-сеанс в Windows frozen EXE**: вызов `prepare_asyncio_runtime()` добавлен; CI проверяет executor/DNS готового EXE без ключа. Это не заменяет живую сетевую проверку упакованного EXE с локальным токеном.
3. **Проверить реальный формат REST/WebSocket Finam**: protobuf Decimal/timestamps, маршруты авторизации, соответствие подписок, нативность M5/H4, финальные/формирующиеся свечи и границы закрытия.
4. **Проверить задержку строго по правам и наблюдениям.** Не отображать отсутствие задержки как факт по одной доступной подписке; неопределённое право не подтверждает 0 минут.
5. **Восстановить требуемые пользовательские элементы интерфейса**, утраченные при упрощении Finam-окна (расширенный правый список/панель, диагностический экспорт и индикаторные элементы) только после сверки пожеланий с текущими скриншотами.
6. Проверка H1/H4/D/W/M и FVG с TradingView на одинаковых данных, частично подтверждённая история и новая live-диагностика.
7. Улучшение обновления SQLite, инвалидации кэша и обработки разрыва потока при реальных данных; тестирование стабильного завершения EXE с активным Finam WebSocket.

## Регламент переключения

- **Перед началом:** `git status --short` → `git fetch origin` → `git switch main` → при чистом дереве `git pull --ff-only origin main`; затем прочесть `AGENTS.md` и эту карточку.
- **Перед передачей:** тесты → `docs/CURRENT_STATE.md` → commit + push → проверка remote SHA/CI. Написать следующему исполнителю «Продолжай FlowDesk», не требуется копировать чат.
- Никто не работает параллельно над одним HEAD; незапушенные изменения из локального Codex в GitHub не видны.
