## 1. Продукт, цели и границы

FlowDesk — Windows x64 торговый **аналитический** терминал Python 3.15 / PySide6. В нём строятся свечные графики, FVG, потоки приказов №1–3, структурная ломаная, IDM/старшая ликвидность, рыночная структура и сводка по таймфреймам.

**Только получение и анализ котировок**; никакого выставления торговых заявок. Пользователь работает последовательно через ChatGPT (удалённые GitHub-правки и анализ) и локальный Codex (редактирование и локальные проверки). Репозиторий и актуальная ветка `main` — общий источник изменений. Текущая версия: **0.2.26**; номер сохраняется.

## 2. Эталон расчётов

- **TradingView v2.11 H1 + H4**, основной pinned source `reference/TradingView_v2.11.pine`; SHA-256 `CC2E1422F6D865C7D4814B7FF7CD4EEA82F87EB89642E8EF5F158A47B85D057F`.
- Все **74 настройки** через ⚙, включая BOS/CHOCH/MAX/MIN, VWAP, FVG, поток и диагностику. Более раннее желание удалить некоторые блоки заменено поздним решением воспроизвести полный v2.11; не удалять их самовольно.
- Таймфреймы: M1, M5, H1, H4, D1, W1, MN1 (на экране: 1м, 5м, 1ч, 4ч, Д, Н, М).
- На M1/M5 поток проектируется от **подтверждённого H1**, а не вычисляется независимо по каждой минуте. H1 получает старший контекст H4/D/W/M, H4 — D/W/M, D — W/M, W — M. По ТФ сводка H1/H4/D/W/M.
- Для FVG значимы время создания/пробоя, активный родитель и собственный/старший источник, подтверждение баров, правила потоков №1–3 и ограничение отображения (не обрезать расчётный контекст по лимиту рисунка).
- Структурная ломаная, текущий и прошлый поток, IDM, диагностика, настройки цветов/ширин/шрифтов должны сохраняться.
- Полная визуальная эквивалентность Pine **не доказана**; необходима сверка идентичной истории, TF, сессии, `asof` и input.

## 3. Источник рыночных данных — только Finam (решение 15.11.2026)

- Свечи, цены, WebSocket, справочник, шаг цены и экспирации — только Finam Trade API. MOEX ISS разрешён исключительно для топ-20 акций: точный VALUE TQBR за 20 завершённых сессий и необходимые метаданные акций. Запросы дат РФ RFUD и резервные календари CME/ICE удалены.
- Локальный токен «Просмотр» хранится в Windows Credential Manager. Ввод: ⚙ → «Приложение». Авторизация HTTPS получает JWT и права; account_id для GetAsset остаётся только в памяти и запросе, не в логах/интерфейсе.
- HTTP и WebSocket работают автоматически. WebSocket получает открытый инструмент; HTTP даёт первоначальную историю, восстановление и периодическую сверку. Общая очередь, максимум три запроса одновременно и 180 запросов/минуту с приоритетом графика.
- Последние три свечи обновляются с перекрытием; история не обрезается. SQLite хранит свежесть и курсоры подкачки. Скринер проверяет три инструмента одновременно и использует общие данные/расчёты; повторные проходы не накладываются.
- При отсутствии Finam-экспирации автоматический переход заблокирован, точный активный контракт доступен. Ролловер остаётся за один календарный день до подтверждённой даты в календаре биржи. Приоритет у явного calendar Date Finam.
- Полный паритет с TradingView и длительная свежесть живого потока требуют самостоятельной проверки; успешная сборка и тесты не являются подтверждением этих свойств.

## 4. Требования к интерфейсу

- Полный фирменный знак FD и надпись FLOWDESK в заголовке; для Windows иконки — утверждённый тексто-независимый FD-монограм.
- Открывать сохранённый инструмент при запуске без отдельной обязательной кнопки загрузки. Правый список/поиск/выбранный инструмент пользователь желает сохранять; новая Finam GUI пока представляет упрощённый список примеров и поле тикера/MIC, а не полный прежний динамический MOEX-список. Не считать запрос полностью выполненным.
- Кнопки ТФ 1м, 5м, 1ч, 4ч, Д, Н, М; Д/Н/М показывать с корректной календарной меткой начала по источнику/бирже. Прежние MOEX отметки 00:00 МСК **не являются универсальным временем для США**.
- Время свечи на графике и под перекрестием — Candle.time (начало исходной свечи). Нельзя подменять его временем запроса/доставки пакета или последней сделки, а саму свечу — ценой котировки.
- Плавное движение перекрестия; кэш статического рисунка QPixmap, QPainter поверх для курсора/оси/OHLC. Масштабирование колёсиком, перемещение графика и цена/время по осям остаются отзывчивыми.
- Обработка обычных порций котировок не должна сбивать статус `ПОТОК · ISS+` / `FINAM · ПОТОК` или показывать ненужные сообщения «Открытие». При реальном разрыве показывать переподключение и доступную причину.
- При закрытии Windows EXE должен корректно завершаться основной процесс, в том числе при активном WebSocket/HTTP.

## 8. Риски и незавершённость — не выдавать за готовое

1. Вызов `prepare_asyncio_runtime()` перед Finam worker добавлен; проверка готового EXE теперь отдельно упражняет executor и localhost DNS. Длительное сетевое соединение упакованного EXE с локальным ключом проверить отдельно.
2. Проверить официальные REST/WebSocket ответы Finam: auth/JWT, тип timestamp/Decimal, правильность BARS/QUOTES, время закрытия/неполные бары, ошибки прав MIC и сверку потерь.
3. Проверить типовую архитектуру истории и потоковых M1/M5/H1/H4/D/W/M; хватает ли REST для стабильной истории индикатора, не выдумывать недостающие бары.
4. Проверить и по необходимости восстановить UI: правый список, диагностику, подсказки, настройки, таблицы, точность меток и ощущения TradingView.
5. Проверить паритет Pine на том же источнике и при тех же доступных данных, особенно американские вечерние и праздничные сессии.
6. Стабильность SQLite и кэша при обновлениях/смене инструмента; корректное закрытие потоков и реакция на ошибку Finam.
7. Не повышать версию и не возвращать MOEX в активный GUI без просьбы.

## 9. Разделение фактов и обещаний

- `PASS` CI/EXE означает, что проект собирается, старые и новые моковые тесты проходят, Qt-окно открывается, EXE закрывается.
- `PASS` не означает наличие реальных прав на NYSE/NASDAQ, нулевую задержку котировок, поточную доставку всех ТФ, полный архив, отсутствие пропусков или точное совпадение TradingView.
- Для живых котировок пользователь вводит ключ **локально**. Внешние скриншоты ошибок должны исключать отображение секретов.
- При передаче работы всегда указывать конкретный HEAD, CI и непроверенные области; не терять порядок решений из двух чатов.

## 10. Как продолжать

Перед каждой задачей: прочитать `AGENTS.md` + `docs/CURRENT_STATE.md`, сверить `origin/main` с локальной копией, остановиться при незапушенных изменениях другого исполнителя. После задачи: тесты + короткая запись в CURRENT_STATE + commit/push + CI. Никаких длинных ручных экспортов чата для каждой передачи.
