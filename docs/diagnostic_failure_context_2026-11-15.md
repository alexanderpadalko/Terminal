# Причины сбоев в локальном журнале — 15.11.2026

Исходная общая версия перед изменением: **8c05731**. Сохранены новые изменения темы, SQLite backup/recovery и остальные предыдущие исправления. Версия **0.2.26**, Pine/FlowEngine/74 настройки, источники/40 инструментов и UI не менялись.

## Исправленная потеря данных

При отказе справочника worker передавал только `type(exc).__name__`, а журнал искал HTTP-код в строке. Поэтому реальные HTTP/сетевые причины терялись: `catalog_unavailable http=none`. GUI затем мог продублировать уже обезличенную ошибку. `catalog_complete` записывался даже после неуспешного запроса, без пометки кэша.

Теперь журнал получает исходное исключение и отбирает только разрешённые поля:

| Поле | Содержимое |
|---|---|
| `http` | Проверенный числовой HTTP status либо `none` |
| `kind` | http, timeout, dns, tls, connection, network, invalid_response, cancelled, storage, unknown |
| `error_type` | Имя из фиксированного списка; неизвестные классы — other |
| `stage` | Этап: каталог, разрешение фьючерсов, roll state, снимок списка, рейтинг MOEX и др. |
| `operation` | Фактический запрос: auth/token_details/catalog/asset_details/candles/quotes; только код, без URL |
| `page` | Номер страницы справочника 1–150; курсор никогда не записывается |
| `elapsed_ms` | Длительность этапа, ограниченное числовое значение |
| `retry_after_s` | Проверенный Retry-After, если он присутствует |
| `outcome` | ok / partial / fallback / cancelled для завершённой проверки |

Авторизация перед первой страницей сохраняет `stage=catalog operation=auth page=1`. Отказ на последующей странице сохраняет её номер. Сетевой тип распознаётся по bounded cause/context/URLError.reason, в том числе после `raise ... from None`. Если библиотека передала только неизвестный текст, причина остаётся unknown/network, без угадывания по содержимому сообщения.

Также сохранены реальные причины отказа GetAsset, рейтинга MOEX (включая прежде проглоченный fallback), записи списка фьючерсов и автоматических SQLite-снимков. Предусмотренный fallback/частичная проверка теперь отличаются от успешного завершения. Сетевые алгоритмы, число повторов, кэш и расписание запросов не менялись.

## Приватность и проверки

- Путь остаётся `%USERPROFILE%\.flowdesk\logs\diagnostics.log`; ротация 1 МБ × текущий файл и три архивных. Автоматической отправки нет.
- Никогда не записываются сообщения/представления исключений, произвольные имена классов, секреты/JWT/account_id, URL/query/cursor, заголовки/тела запросов и ответов. Сохраняются только коды и нормализованные числа. Legacy string-вызовы могут дать только извлечённый HTTP-код, без копирования текста.
- Новые regression/security тесты: HTTP 429/503, auth 403, отказ второй страницы, испорченная схема, timeout/DNS/TLS/reset через вложенный URLError, самоссылочная цепочка, запрещённый `__str__`, приватные имена/поля, NaN/Infinity, fallback и ошибки roll state/MOEX. До реализации четыре новых тестовых метода падали; после реализации весь набор **558 тестов, OK (1 локальный предусмотренный skip)**, 35.276 с, изолированный профиль/null keyring. Генераторы pinned v2.11/**74 настройки** успешны.
- Никакой реальный отказ Finam этой проверкой не провоцировался; сетевые ошибки воспроизводились локальными фикстурами. **Историческую причину сбоя 15.11.2026 15:13 МСК восстановить невозможно**: изменения сохраняют сведения только о будущих событиях после обновления EXE.
