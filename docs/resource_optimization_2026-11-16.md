# Оптимизация CPU и памяти —16.11.2026

Причина запроса: после включения максимального архива пользователь сообщил о высокой нагрузке CPU/RAM. Рабочего процесса FlowDesk при первичном чтении процессов уже не было, поэтому выполнен воспроизводимый профиль на отдельных существующих копиях сохранённых архивов SBER/CR; пользовательские БД/цены не менялись.

## Причины и изменения

- Upsert сбрасывал все analysis entries символа, а FinamMarketService не передавал предыдущие TF в уже существующий механизм pipeline reuse. Теперь совместимые источники и подтверждённые блоки сохраняются. Изменённый блок пересчитывается, неизменный при prepend переносится с корректировкой индексов структуры/FVG/flow/market. Переход закрытия, настройки и исторические исправления не маскируются кэшем. Pinned Pine/FlowEngine формулы прежние; `Analysis.history_blocks` — только хранилище результатов.
- Ключ H1/H4/DWM раньше удерживал большие M1/M5 массивы, которые pipeline этих графиков не анализирует. Теперь key содержит только нужные TF; M1/M5 по-прежнему участвуют в подготовке канонических свечей и их изменения проверяются через полученные H1/H4. Никакой raw/видимой истории не обрезается. LRU ограничен12 записями/250000 единицами (`candles + flows + 2×liquidity_audit`), активный график закреплён. Это эвристический бюджет объектов, **не байтовый лимит RAM**, один большой активный график допускается. Summary не держит Analysis через ссылку на самого себя.
- Scan использует один согласованный source snapshot вместо трёх полных чтений. Candle создаются из SQLite-курсора без одновременного хранения всей промежуточной raw rows-list. Чтение source observations/coverage остаётся в той же SQLite read transaction.
- Максимальный архив продолжается с тех же курсоров/границ, по умолчанию одним worker. После каждого окна lock/HTTP уже освобождены; пауза max(0.5с,4×потраченное thread CPU-время), отмена проверяется каждые<=0.1с. Ориентир<=20% одного ядра для **архивного worker**, не всей программы. Архивный refresh графика30с вместо5с; обычные котировки/HTTP не замедлены. **Полный архив будет загружаться дольше.**

## Измерения и границы доказательства

Одинаковые исходные архивы, одинаковые настройки, H1, изменение high последней свечи на0.01. Fresh replay и reuse сравниваются по candles/segments/FVG/flows/pairs/confirmed FVG/market/liquidity audit/asof/tick/source. Расхождений нет.

| Архив | Полный пересчёт | С повторным использованием | Ускорение |
|---|---:|---:|---:|
| SBER |4.1625с|0.2089с|19.93×|
| CRZ6 |2.6558с|0.2132с|12.45×|

В отдельном двухинструментном headless-профиле peak RSS снизился примерно на22% (точные значения в evidence). Это **не процент снижения общей загрузки CPU или RAM установленного EXE**. Cold полный replay при первом открытии/смене настроек/необходимой исторической коррекции остаётся; долгие много лет M1 требуют памяти для самого активного графика. Все raw/prepared количества сохранены. В evidence cold-фаза измерялась под cProfile, update-фаза без него; сравнение update/fresh выше выполнено без cProfile на обеих ветках.
