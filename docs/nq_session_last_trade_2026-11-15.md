# NQZ26: OHLCV одной сессии, Close последней цены Finam

Последнее решение пользователя: **«Только Финам — последняя цена сессии»**. Оно заменяет прежнее требование расчётного Close. Исправление подготовлено поверх актуального `origin/main` **f32149c** с сохранением версии **0.2.26**, всех пользовательских UI/FVG-изменений, 74 настроек и списка из 30 инструментов.

## Что исправлено

Прежняя политика `nq-session-settlement-1` соединяла правильные сессионные OHL с native Finam D1 Close, который в части архива относится к другому временному окну. На 28 октября он оказался ценой следующей ночи. Совпадение нескольких ноябрьских дат с settlement не подтверждало правильность октября.

Новая политика **`nq-session-last-trade-1`** применяется только к **NQZ26@XCME**:

- Все дневные O/H/L/C/V получаются из Finam H1 внутри одной CME-сессии, включая вечернее начало. Close — последний доступный H1 Close внутри неё. Проверенные праздники сохраняют отдельные физические сегменты и соответствующую trading date.
- Недели и месяцы строятся из этого же дневного ряда, без подстановок native Close и без смешивания разных правил по датам. Native D/W/M используются только для сохранения границ доступного архива.
- Новый хэш политики инвалидирует старый производный settlement-кэш. Исходные свечи не переписываются. Набор D/W/M публикуется целиком; неполная новая семья не заменяется ошибочными native ценами. При последующем сбое сохраняется согласованный Last-снимок без подтверждения старых черновиков.
- Новые свечи NQ не используют `settlement_close`; общее поле оставлено для совместимости. Неизвестный календарь не разрешает возврат к native D/W/M. Подкачка, лимиты очереди, курсор и отмена сохранены.

## Проверка реальных цен

Использована изолированная копия ранее полученного read-only архива Finam; новых сетевых запросов в этом прогоне не было. Рабочая база, ключ и настройки пользователя не менялись.

Для 28 октября старый C **29642.00** из следующего ночного окна больше не используется. TV **29979.50** на присланном скриншоте — settlement, а не Last. В TradingView для сопоставления режима нужно выключить **«Расч. цена» / Settlement as close**. Это не обещание точного совпадения всех источников/объёмов: [TradingView о Last и settlement](https://www.tradingview.com/support/solutions/43000685268-can-i-switch-settlement-and-last-prices-as-close-for-futures/). В [Finam REST Bars](https://api.finam.ru/docs/rest/) нет отдельного поля исторического settlement; внешний ценовой фид не подключён.

В архиве **2434 H1**. Все **104 D** проверены по собственным физическим H1-сегментам: O первого, H/L экстремумов, C последнего, сумма V. Все **22 W /6 M** проверены по той же семье D. **85 дневных Close** отличаются от старой ошибочной политики. Сохранились **6 месяцев**, из них **5 закрытых**; SHA-256 исходных рядов до/после одинаков. Графический monthly consumer получил новую политику, скринер завершился без ошибки; его цена была подставлена из последней известной сессии, это не проверка живой котировки.

Evidence: [безопасный JSON](evidence/nq_session_last_trade_archive_2026-11-15.json). Первый июньский источник начинается внутри сессии и остаётся отмеченным `left_partial`. H4-покрытие в этой изолированной копии неполное; его алгоритм данным исправлением не менялся. Другие контракты, Binance, экспирации и индикаторные правила не затронуты.
