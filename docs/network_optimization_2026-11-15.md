# Finam: общая загрузка и единственный источник экспираций

По решению пользователя 14–15.11.2026 все цены, свечи, метаданные и даты экспирации получает Finam. MOEX ISS остаётся только для точного топ-20 акций по VALUE TQBR за 20 завершённых сессий. Запросы дат RFUD и код календарей CME/ICE удалены.

## Загрузка и расчёты

- `RequestCoordinator` общий для графика, скринера, метаданных и авторизации. До 180 HTTP-запросов в минуту с равномерным запуском, максимум три активных. Приоритеты: график 0, каталог 5, скринер 10, архив 20. Одинаковые одновременные GET объединяются. При 429 — общая отменяемая пауза Retry-After/60 с, один повтор; следующий отказ завершает проход с честным состоянием ограничения.
- `FinamMarketService` объединяет обновления одного symbol/TF. Общий lock не удерживается во время сети и расчёта. SQLite WAL хранит свечи, время обновления и курсор архива; проверки свежести читают три последних бара по индексу, а не весь архив.
- После первоначального заполнения запрашиваются последние три свечи с перекрытием. Сохранённая история не обрезается; полное обычное окно сверяется раз в сутки. Интервалы без свежего потока: M1 60 с, M5/H1 300 с, H4 900 с, D 1800 с, W 3600 с, M 14400 с.
- Свежесть потока проверяется для каждого TF: время получения не старше 90 с, исходная свеча покрывает время наблюдения с учётом прав на задержку. При выполнении условий HTTP-сверка — не чаще 900 с (старшие периоды сохраняют более длинный интервал). Старый снимок/одна котировка/handshake не доказывают полноту свечей. Переподключение и обнаруженный разрыв требуют HTTP-восстановления; повторные отказы и пустые ответы не вызывают частый цикл.
- Скринер работает тремя исполнителями внутри фонового QThread. Сначала публикует все первичные результаты, затем делает архивную дозагрузку с низким приоритетом. Проходы каждые пять минут не накладываются. В панели обычный счётчик «Проверено X из 38». M1 нужен только для резервной цены при отсутствии LAST; последняя пригодная потоковая котировка используется повторно.
- Общий кэш расчётов учитывает все свечи/исправления, появление и закрытие баров, расчётные настройки. При неизменной истории обновление одной цены не запускает весь анализ. Не менялись Pine v2.11, структура, FVG, фильтрация аукционов, 74 настройки и версия 0.2.26. Фиксированные минимумы свечей не восстановлены.
- Циклическая сборка мусора Python перенесена на таймер основного Qt-потока: в локальном тесте зафиксирован native access violation при автоматической GC в рабочем потоке расчёта. Подсчёт ссылок не меняется; исходный режим GC восстанавливается при выходе приложения. Очередь и скринер дополнительно проверяются в frozen runtime probe без токена.

## Экспирации

GetAsset принимает исходное написание `SiZ6@RTSX` / `EuZ6@RTSX`, а внутренние ключи сравниваются без регистра. При HTTP 400/404 запрос повторяется с единственным account_id из локальной авторизации; идентификатор не выводится и не сохраняется в отчёте.

Приоритет у явного calendar Date Finam. Timestamp используется только при отсутствии подходящей календарной даты. Это устраняет сдвиг даты США на предыдущий день из-за UTC-полуночи. Отдельно исправлен год в подписи январского Brent: `BRNF27@IFEU` остаётся `BRNF2027`, хотя Finam-дата экспирации относится к ноябрю 2026.

До дня переключения запрашивается только карточка текущей точной серии; далёкие серии не требуют GetAsset. При неизвестной дате автопереход блокируется. За один календарный день до подтверждённой даты проверяется следующая действующая серия той же MIC; сохранённое состояние не откатывается при сбое.

Живой запрос подтвердил **все 14 дат** исключительно от Finam. Si и Eu: **17.12.2026**. Четыре бессрочных контракта даты не требуют. Полный безопасный список — в evidence.

## Живой замер и пределы проверки

Замер использовал отдельный SQLite backup уже сохранённой истории. Исходная база, токен, настройки и сохранённый ролловер пользователя не изменялись. Рейтинг акций взят из имеющегося подтверждённого локального кэша; в этом замере MOEX не запрашивался. Фоновая архивная дозагрузка исключена из времени первичных результатов. Это не замер запуска с полностью пустой базой и не сравнение со старой сборкой.

Сигнальные направления по каждому инструменту совпали между проходами. В исходной итерации GetAsset потребовал 158 запросов на текущие и следующие серии; после ограничения запросов нужной текущей серией — 28 (два на каждую из 14 карточек). Полный каталог Finam занял 43 запроса, авторизация — 2.

Данные: `docs/evidence/finam_optimization_2026-11-15.json`. Это наблюдённые времена вне активных торгов; они не гарантируют ту же скорость во время сессии, отсутствие задержки или паритет с TradingView. Отдельный общий пятилетний cutoff месячной архивной подкачки остаётся известной задачей и этим изменением не расширяется.

Проверка: **498 тестов, OK (локально 1 пропущен)**, включая очередь/паузы/отмену, параллелизм, дедупликацию, исправления истории, свежесть по TF, восстановление и Finam-only экспирации. Эталон и 74 настройки воспроизведены. Windows CI и готовый EXE фиксируются в CURRENT_STATE после завершения.
