# FlowDesk for Windows — проверочная версия 0.2.10

**Исходник в репозитории:** `reference/TradingView_Structure_FVG_VWAP_Screener_H1_v2.04_IDM_fix.pine` — историческая база v2.04. **Для текущего сравнения используется предоставленная диагностика TradingView v2.09**, поэтому полный паритет с действующей v2.09 пока не подтверждён.

**Платформа сборки:** Windows 10/11 x64, CPython **3.15.2 stable**, PySide6 Essentials **6.12.0 stable**, PyInstaller **6.22.3 stable**, tzdata **2026.4**. Версии зависимостей закреплены для воспроизводимости.

## Изменения 0.2.10 — правило №1 на H1/D1/W1/MN1

- Правило №1 теперь меняет подтверждённый поток с приоритетом **№2 → №1 → №3**. Требуются пробой рабочего FVG, живой встречный FVG и выбранный встречный захват старшей ликвидности. Пробой допускается на свече захвата или позже; встречный FVG должен сформироваться строго позже захвата.
- Иерархия повторяет v2.09: H1 использует D1/W1/MN1, D1 — W1/MN1, W1 — MN1, MN1 работает без старшего подтверждения. Достаточно одного действующего выбранного события. Старшие состояния доступны только после закрытия источника; незакрытая свеча не переключает поток. На M1/M5 передаётся закрытый H1, включая однократные события №1.
- Встречные зоны для №1 хранятся независимо. Пробой последней не уничтожает старую живую зону. Привязка учитывает предыдущее плечо, внешние свечи и ожидание подтверждения собственного плеча; время образования зоны сохраняется при поздней привязке. Рабочая зона нового потока выбирается отдельно среди зон того же движения.
- В журнале интерфейса появился №1. Экспорт содержит проверки, причины блокировки и использованное подтверждение, в том числе для D1/W1/MN1. Старый автономный `rule1_shadow.py` сохранён для сравнения, но больше не выдаёт теневой расчёт за действующий поток.
- Запрос MOEX расширен с трёхлетнего окна до доступного архива H1. D/W/M по-прежнему строятся из очищенных часов; границы календаря и сессия не подменяются нативными дневными свечами. При превышении ёмкости загрузчик отказывается от усечённого архива. **Первый доступный бар, старые биржевые режимы и календарь до 2024 года ещё требуют сверки**; запрос архива не доказывает полноту истории TradingView.
- **114 локальных тестов прошли.** В сценарии со скриншота реальные D1 AFKS и явно переданное месячное состояние Pine воспроизводят №1 10.11: прежний диапазон 7,989–9,306; первый FVG 8,670–9,042; встречный FVG 9,054–9,150; начало движения 08.11; захват месячного FVG 12,777–12,941 от 30.06. **Это проверка потребления заданного старшего состояния, а не доказательство его восстановления из MOEX**. Трёхлетняя история сама по себе даёт другую пару MAX/MIN и не воспроизводит этот результат.
- Полный паритет с v2.09, вся история №2/№3 и время закрытия D/W/M по биржевой сессии остаются неподтверждёнными. Локальный runtime для тестов — Python 3.12; целевая сборка — закреплённый стабильный Python 3.15.2. Отдельный сетевой CI-прогон сохраняет входную историю и результат без подстановки уровней из скриншота.
- Первый сетевой прогон 11.11.2026 завершился `ConnectionResetError` со стороны соединения с MOEX, до получения истории. Добавлены три попытки запроса при временных сетевых ошибках. Сетевая доступность не является обязательным условием сборки; результат хранится отдельно и не выдаётся за пройденную сверку.

## Изменения 0.2.9 — подтверждение закрытия и полная загруженная история

На H1/D1/W1/MN1 публикуется последний подтверждённый поток; на открытой свече сохраняются его направление, начало, рабочий FVG и время последнего события. Тень может расширить диапазон только при неизменных направлении и начале движения, как в ограничении Pine `f_liveFlow`.

Рассчитываются **все загруженные свечи**, одинаково на собственном и младшем графике. **Сетевой диапазон MOEX остаётся прежним — около трёх лет H1**; недостающая ранняя история W1/MN1 не объявляется восстановленной.
- Кнопка **«Добавить старший CSV»** принимает H1/D1/W1/MN1 того же инструмента и торговой сессии, в том числе несколько файлов за один импорт. На M1/M5 H1 служит источником потока; длинные D/W/M можно добавить и поверх MOEX. Источник каждого ТФ сохраняется отдельно; тикер в произвольном OHLCV CSV требуется проверить вручную. Неопределённый ТФ выбирается явно.
- В диагностике добавлены момент расчёта, число закрытых/формирующихся свечей, фактические начало/конец истории и происхождение каждого источника. Полнота истории всегда остаётся неподтверждённой; число свечей не выдаётся за проверку паритета.
- **95/95 локальных тестов прошли**, включая 12 новых проверок: открытый/закрытый бар на четырёх ТФ, реальный последний OHLCV AFKS, сохранение опубликованного FVG, полный H1-ряд и длительный месячный CSV. Локально использован встроенный проверочный Python 3.12; целевая Windows-сборка по-прежнему использует закреплённый **Python 3.15.2 stable**. Workflow запускается также для pull request и проверяет Qt перед созданием EXE.

## Изменения 0.2.6 — исключение аукциона открытия **на всех таймфреймах**

- **Единое правило источника:** аукционные свечи открытия удаляются **до** структуры, IDM, FVG, потоков и теневого №1. После удаления трёхсвечные FVG строятся по последовательным **оставшимся** свечам; искусственные свечи и ценовые уровни не подставляются.
- MOEX TQBR: M1 очищается по минутному окну аукциона; M5 пересобирается из очищенных M1 (никакой аукционной цены в O/H/L/C/V). Для H1 исключается целый час, если весь его биржевой объём относится к аукциону открытия (стандартные отдельные часы 06:00 и 09:00). Не удаляем просто нулевую свечу и не угадываем по объёму.
- **D1, W1, MN1 берутся только из очищенного H1**, а не из нативных свечей ISS, куда аукционная цена могла уже попасть. Выходные торговые сессии MOEX относятся к следующему торговому дню (обычно понедельнику); этот перенос учитывается при формировании старших периодов.
- Изменение истории биржи: **до 27.01.2025** аукцион обычных акций по будням был **09:50–10:00**, после возобновления утренних торгов — **06:50–07:00**; в торговые выходные — **09:50–10:00**. Для исключительных дат предусмотрен файл `~/.flowdesk/auction_windows.json`, например `{"2026-12-12": ["08:50", "09:00"]}`. Если окно аукциона смешано с торгами внутри одной H1, загрузка выдаёт ошибку вместо подачи нечистых H1 на расчёты: для этой даты потребуется восстановить H1 из M1.
- Загрузка MOEX использует **один** очищенный H1-источник для H1/D1/W1/MN1 и отдельный очищенный M1 для M1/M5. В JSON `session_info` указываются версия политики, начало/конец истории, число удалённых H1-свечей и исключительные даты. Для CSV M1/M5/H1 фильтр также применяется; импорт D/W/M предполагает, что CSV экспортирован из уже выбранной сессии TradingView.
- **Предел покрытия:** старшие периоды доступны лишь за диапазон загруженного H1 (по умолчанию до 1095 календарных дней, а не 1000 месячных свечей). На особых торговых датах и инструментах без утренней сессии нужен дополнительный календарь; для иных режимов торгов TQBR-фильтр не используется. Цена аукциона закрытия, если она входит в обычный торговый час, этим способом ещё не удаляется: для полной внутрисвечной очистки необходим минутный источник.
- На сохранённой AFKS H1 версии 0.2.5: **2705 исходных → 2540 очищенных H1** (165 аукционных часов удалены), исчез ложный FVG 9,065–9,208 ₽, поток остаётся **ЛОНГ 8,527–9,306 ₽**. На сохранённой M5: **2561 → 2547** свечей (14 часов аукциона в пятиминутном ряду); перенос H1→M5 остаётся согласованным. Проверено **72/72 локальных теста**. Живые ISS-запросы и Windows EXE пока отдельно не проверены.
- **Правило №1 остаётся теневым**, реальные изменения потоков по-прежнему только №2/№3; полная эквивалентность Pine ещё не подтверждена. Для корректного сравнения ставьте одинаковую торговую сессию в TradingView и FlowDesk.

## Изменения 0.2.4 — теневой расчёт правила №1 (без изменения потока)

- Для **каждой закрытой H1-свечи** рассчитывается гипотетическое правило №1. Проверяются наличие первого рабочего FVG, время его пробоя, наличие подходящего встречного FVG, направление и доступность D1/W1/MN1 подтверждения, порядок «захват → FVG» и «захват ≤ пробой».
- Приоритет **№2 выше №1 выше №3** диагностируется отдельно: `OVERRIDDEN_BY_RULE_2`, `WOULD_PREEMPT_RULE_3` и `WOULD_TRIGGER_RULE_1`. Повторное сохранение уже сработавшего гипотетического условия в том же эпизоде отмечается `PERSISTING_AFTER_SHADOW_TRIGGER`, а не новым событием.
- Подробный JSON `rule1_shadow` содержит все строки H1 (`rows`), булевы проверки и причины блокировки (`checks`, `blockers`), обнаруженные гипотетические события (`hypothetical_events`), статистику и последнюю **закрытую** свечу. На M1/M5 объект экспортируется из того же H1-родителя.
- **Важные ограничения**: происхождение встречного FVG реконструируется по Python-структуре, а не идентичному Pine-алгоритму привязки FVG; D1/W1/MN1 подтверждения из v0.2.3 тоже ещё предварительны. Даже `WOULD_TRIGGER_RULE_1` — не подтверждённый сигнал. Гипотетический №1 не меняет последующие потоки, поэтому это не альтернативный торговый бэктест.
- Не внесено **ни одного** изменения в обработчик реального потока H1, правила №2/№3 и проекцию H1→M5. Пройден **51/51 локальный тест**; по **2 723 историческим свечам AFKS H1** сравнение со снимком v0.2.3 дало **0 различий** в `side`, `lo`, `hi`, `start`, `rule`, `last_change_rule`.
- Техническая проверка на агрегированных из H1 дневных/недельных/месячных свечах выполнялась **только** для запуска теневого расчёта. Агрегация не является внешним подтверждением уровня D/W/M и не заменяет проверку Pine v2.09.

## Изменения 0.2.3 — предварительная диагностика старшей ликвидности для правила №1

- Подключён **расчётный аудит D1 / W1 / MN1 для H1**: снятие рабочей пары MAX/MIN с IDM, первое касание рабочего FVG старшего ТФ, отмена FVG-захвата после закрытия свечи собственного ТФ, конфликт одновременных захватов двух направлений.
- Используются **только закрытые свечи старших таймфреймов**. При отсутствии исходного D1/W1/MN1 программа не выдумывает событие. При равном времени подтверждения приоритет у более близкого ТФ (D1 перед W1 перед MN1).
- Для M1/M5 аудит рассчитывается в отдельном H1-источнике, а не на младших свечах. **История потока, правила №2/№3 и перенос H1→M5 не меняются.**
- В JSON «Экспорт диагностики» добавлен объект `rule1_higher_liquidity`: события захвата, конфликты, последнее выбранное подтверждение и состояние доступности каждого старшего ТФ.
- **Правило №1 ещё не переключает направление.** Это диагностический контур, НЕ подтверждённый прямой проверкой каждого события с Pine v2.09. Расчёты сессий/времени свечей MOEX и рабочей пары старшей ликвидности могут иметь отличия от TradingView; этап включения правила №1 будет отдельным.
- **36/36 локальных тестов** проходят. На сохранённой истории AFKS проверено, что все 2 561 состояний M5 и их источники H1 остаются полностью неизменными (8,527–9,306 ₽ в конце ряда). Дополнительно прогонялся аудит на агрегации старших свечей из сохранённых H1, но такой прогон **не является** сравнением реальных D/W/M со TradingView.

## Изменения 0.2.2 — первый FVG после структурного разворота №2

- **Исправление логики:** при правиле №2 без встречного FVG сохраняется неопределённый `seed_impulse` (эквивалент Pine `na`), а не индекс предшествующей свечи. Новый восходящий FVG не должен ошибочно отсеиваться как часть прежнего импульса.
- На **полной** сохранённой диагностике AFKS H1 от 10.11.2026 (2 722 свечи, локальный повторный расчёт): текущий ЛОНГ **8,527–9,306** против **7,989–9,306** в версии 0.2.1. По графику TradingView v2.09 обе границы 8,527 и 9,306 совпали.
- В данном повторном расчёте №3 подтвердился 06.11.2026 в 08:00 МСК. **Точное время смены потока и полное совпадение истории с Pine пока не подтверждены**; алгоритм кандидатов FVG ещё предварительный, правило №1 со старшей ликвидностью не реализовано полностью.
- Добавлен отдельный регрессионный тест на №2 без FVG → первый допустимый FVG → №3. Сохранены существующие тесты передачи закрытых H1 на M1/M5 без будущих значений.
- Программа остаётся **экспериментальной**, не выставляет торговые заявки и не предназначена для принятия торговых решений.

## Изменения 0.2.1 — диагностика расхождения границ H1

- После сравнения AFKS M5 с TradingView v2.04 10.11.2026 обнаружено расхождение: на скриншоте TradingView нижний уровень потока **ориентировочно 8,539**, верхний **около 9,306**; FlowDesk 0.2.0 показывает **7,989–9,306**. Цены с TradingView прочитаны визуально, точный эталон ещё не выгружен.
- **Запрещена подмена значения 0 уровнем IDM**: происхождение нижней границы нужно определить из алгоритма создания H1-потока. Правило №1 и MTF-старшая ликвидность в текущем движке по-прежнему не реализованы; поэтому расхождение не объявляется исправленным.

- При экспорте M1/M5 в `h1_reference` теперь включены **полная исходная история H1 OHLCV и полная поминутно привязанная к H1 история состояний**, а не только события №2/№3. Это позволит разбирать причину расхождения без экспорта из TradingView.

- Расширены тесты происхождения диапазона; проверено, что диагностическая доработка не изменяет формулы смены потока и переноса H1→M5.

**Важно:** версия 0.2.1 является **диагностической**, а не исправлением самой цены нижнего уровня. Изменение чисел без переносa отсутствующего правила №1 было бы ложной подгонкой под скриншот. Не использовать для торговых решений.

## Изменения 0.2.0 — перенос закрытого H1 на M1/M5

- **Критическое исправление:** на M1 и M5 больше **не запускается собственный FlowEngine**. Потоки, уровни, IDM и события приходят только от отдельной истории **H1**.
- Из MOEX ISS часовые свечи H1 загружаются отдельно, с более длинной историей (до 3 000), чем M1/M5; это предотвращает короткий старт потока только от последних 14 дней.
- Исторические значения H1 становятся доступными **только после завершения соответствующей часовой свечи**. Для M5 час 20:00–21:00 доступен на закрытии свечи 20:55; для M1 — на закрытии свечи 20:59 (время Москва). На текущей открытой свече учитывается реальное время запроса, чтобы не подсматривать будущую часовую свечу.
- События правил №2–3 на M1/M5 отражаются однократно при закрытии H1, а не повторяются каждую минуту; индексы начала/архива потока переводятся в координаты младшего графика.
- Если H1 не загрузился, младший график продолжает показывать собственные структуру и FVG, но поток помечается **«ОЖИДАНИЕ / H1 недоступен»**, а не заменяется произвольным младшим потоком.
- Для **CSV M1/M5** добавлен импорт отдельной часовой истории того же инструмента (с 0.2.9 — кнопка **«Добавить старший CSV»**). Без H1 потоки на младшем CSV не рассчитываются. Совпадение тикера должен проверить пользователь.
- Экспорт JSON дополнен исходными OHLCV, источником H1 и временем закрытия использованной H1 свечи. Это позволит проверить отсутствие lookahead и сверить котировки.
- Воспроизведено расхождение по диагностикам AFKS от 10.11.2026: старая M5 показывала ШОРТ 8,539–8,918, а после корректного переноса H1 на M5 будет **ЛОНГ 7,989–9,306** на закрытии свечи 20:55 МСК. **Это тест внутренней синхронизации, НЕ доказательство совпадения с Pine.**
- Расширены автономные тесты: появление H1-потока только после закрытия часа, однократность событий, отсутствие lookahead, отсутствие ложного потока при недоступности H1.

**Не завершено:** перенос правила №1 и сверка №2/№3, структурной ломаной и FVG с TradingView 1:1. Параметры H1 по-прежнему предварительные. Версия 0.2.0 не предназначена для торговых решений и не выставляет заявки.

## Что уже работает

- Нативный оконный интерфейс Qt с интерактивным свечным графиком (колесо = масштаб, перетаскивание мышкой = прокрутка).
- Загрузка **исторических свечей MOEX ISS** для акций, например SBER/GAZP/IRAO (по умолчанию режим торгов TQBR). API публичный, но данные могут поступать с задержкой; это не поток котировок реального времени. По таймфреймам: M1, M5 (агрегация M1), H1, D1, W1, MN1.
- Импорт пользовательских CSV с Time/Open/High/Low/Close/(Volume), экспортированных из TradingView (также поддерживаются русские заголовки).
- Структурная ломаная: материнские, внутренние и цепочки внешних свечей; подтверждённые и формирующиеся плечи.
- FVG: трёхсвечная модель, отбрасывание гэпов по соседним теням, исключение внутренних свечей на M1/M5/H1, балансировка и пробой закрытием, цвет зоны и линия середины.
- Визуализация уровней 0/0,4/0,5/0,6/1 и предыдущего потока, событий предварительного движка №2–3, пары уровней IDM. На M1/M5 используется H1 (после закрытия часа).
- Дополнительные FVG H1/D1/W1/MN1 над младшим графиком (если источник данных доступен).
- Экспорт собственного состояния потоков/FVG в JSON для диагностики; встроены автономные тесты расчётного ядра.

## Что НЕ готово — важно

**Это тестовая сборка, а не подтверждённо совпадающая с TradingView рабочая версия.** Часть расчётного движка перенесена по исходнику, но полной 1:1 эквивалентности нет и сверка на пользовательском историческом экспорте не завершена.

- Условие потока №1 требует полного MTF-подтверждения и правильной отмены/восстановления событий старшей ликвидности — **не реализовано как достоверный сигнал**, поэтому не создаётся ложное событие «№1».
- №2 и №3 реализованы как **предварительная визуальная логика**, не прошли эталонную проверку на выбранном пользователем участке истории.
- Привязка новых FVG к сложным внешним импульсам и исторические уточнения структуры могут отличаться от Pine; библиотека хранит зоны, но не воспроизводит все оптимизации хранения и MTF-публикации из Pine.
- Обработка границ торговых сессий и свечей с High=Low требуется отдельно сверить по бирже. Автоматическое исключение нулевых свечей **не включено**: иначе можно скрытно поменять расчёты.
- На всех ТФ поток подтверждается по времени закрытия исходной свечи, но полное поведение живых диапазонов и остальные MTF-подтверждения ещё не гарантируют соответствия Pine. Для FVG старших ТФ используется отдельное состояние только по закрытым источникам.
- Нет встроенного скринера, VWAP, BOS/CHOCH и MAX/MIN-рисования — таковы последние требования. В частности, MAX/MIN-пара остаётся **в расчёте IDM**, но не рисуется как отдельный блок.
- Никакие сделки или заявки приложение не выставляет. Не использовать предварительные сигналы для торговых решений без независимой проверки.

## Как конечному пользователю запустить готовую Windows-сборку

1. Получить архив **`FlowDesk-Windows-x64-Python-3.15.2`** из GitHub Actions (сборка описана ниже) или папку `dist/FlowDesk` от разработчика.
2. Распаковать целиком, **не извлекая один FlowDesk.exe без соседних файлов**.
3. Дважды щёлкнуть по `FlowDesk.exe`. **Python на компьютере пользователя не нужен.**
4. Программа откроется на явно помеченных синтетических DEMO-свечах. Для реальных данных нажать «Обновить MOEX», либо «Открыть CSV» и выбрать экспорт TradingView.

## Как получить EXE, если его пока нет

Файлы этого исходного проекта нельзя считать готовым `.exe`. PyInstaller **не кросс-компилятор**: Windows EXE собирается на Windows, а не в Linux-контейнере.

**Вариант без установки Python на ваш компьютер (GitHub Actions):** создать приватный GitHub-репозиторий, загрузить туда содержимое этого проекта с папкой `.github`, затем перейти `Actions` → `Build Windows FlowDesk exe` → `Run workflow`; в артефактах успешной сборки появится ZIP со всей папкой программы. Не загружайте приватный Pine-исходник в публичный репозиторий, если не хотите его раскрывать.

**Локальная сборка для разработчика:** установить Python 3.15.2 x64 на машине сборки и запустить `build_windows.bat` (виртуальное окружение, зависимости, тесты и сборка автоматизированы). Требовать установки Python от конечного пользователя не нужно.

## Границы данных

- CSV без часового пояса читается в `Europe/Moscow` по умолчанию. Если экспорт в UTC, используйте ISO-дату с `Z` или Unix timestamp.
- ТФ файла определяется автоматически из шагов свечей, если распознаётся.
- MOEX ISS может отдавать историю с задержкой. Значения на незакрытых барах могут меняться.
- API зависит от режима торгов и типа инструмента; для другого рынка нужен отдельный адаптер.
