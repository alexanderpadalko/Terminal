# FlowDesk for Windows — проверочная версия 0.2.3

**Эталон исходника:** `reference/TradingView_Structure_FVG_VWAP_Screener_H1_v2.04_IDM_fix.pine` (Pine Script v6, версия **v2.04 H1 IDM fix**). Файл эталона включён целиком, не заменён пересказом и не сокращён. Это базовая версия, выбранная в обсуждении, а не экспериментальная v2.07/2.08.

**Платформа сборки:** Windows 10/11 x64, CPython **3.15.2 stable**, PySide6 Essentials **6.12.0 stable**, PyInstaller **6.22.3 stable**, tzdata **2026.4**. Версии зависимостей закреплены для воспроизводимости.

## Изменения 0.2.3 — предварительная диагностика старшей ликвидности для правила №1

- Подключён **расчётный аудит D1 / W1 / MN1 для H1**: снятие рабочей пары MAX/MIN с IDM, первое касание рабочего FVG старшего ТФ, отмена FVG-захвата после закрытия свечи собственного ТФ, конфликт одновременных захватов двух направлений.
- Используются **только закрытые свечи старших таймфреймов**. При отсутствии исходного D1/W1/MN1 программа не выдумывает событие. При равном времени подтверждения приоритет у более близкого ТФ (D1 перед W1 перед MN1).
- Для M1/M5 аудит рассчитывается в отдельном H1-источнике, а не на младших свечах. **История потока, правила №2/№3 и перенос H1→M5 не меняются.**
- В JSON «Экспорт диагностики» добавлен объект `rule1_higher_liquidity`: события захвата, конфликты, последнее выбранное подтверждение и состояние доступности каждого старшего ТФ.
- **Правило №1 ещё не переключает направление.** Это диагностический контур, НЕ подтверждённый прямой проверкой каждого события с Pine v2.09. Расчёты сессий/времени свечей MOEX и рабочей пары старшей ликвидности могут иметь отличия от TradingView; этап включения правила №1 будет отдельным.
- **35/35 локальных тестов** проходят. На сохранённой истории AFKS проверено, что все 2 561 состояний M5 и их источники H1 остаются полностью неизменными (8,527–9,306 ₽ в конце ряда). Дополнительно прогонялся аудит на агрегации старших свечей из сохранённых H1, но такой прогон **не является** сравнением реальных D/W/M со TradingView.

## Изменения 0.2.2 — первый FVG после структурного разворота №2

- **Исправление:** при правиле №2 без встречного FVG значение `seed_impulse` остаётся неопределённым (как Pine `na`), вместо ошибочного присваивания индекса предыдущей свечи. Первый FVG нового импульса больше не отсекается как «старый».
- Повторный расчёт сохранённой диагностики **AFKS H1, 2 722 свечи на 10.11.2026** дал **ЛОНГ 8,527–9,306 ₽** вместо **7,989–9,306 ₽** в версии 0.2.1. На скриншоте TradingView v2.09 границы 8,527 и 9,306 ₽ совпадают.
- В локальном перерасчёте правило №3 срабатывает **06.11.2026 08:00 МСК**. Время события не подтверждено машинным экспортом из Pine; логика отбора FVG остаётся предварительной.
- Добавлен регрессионный тест «правило №2 без встречного FVG → первый FVG нового плеча → правило №3». Локально пройдены **27 тестов**, включая существующие проверки закрытия H1 и передачи потока на M1/M5.
- Правило №1 со старшей ликвидностью **пока не перенесено полностью**. Исследовательская версия без подачи заявок; полное совпадение сигналов с TradingView **не подтверждено**.

## Изменения 0.2.1 — диагностика диапазона H1

- По скриншоту TradingView AFKS M5 нижняя граница потока ориентировочно 8,539, верхняя около 9,306; в FlowDesk 0.2.0 показано 7,989–9,306. Точные значения TradingView пока не подтверждены машинным экспортом.
- Диапазон не подменяется числом IDM вручную. В исходном Pine Script v2.04 правило №1 и старшая ликвидность влияют на историю потока; в текущем Python-движке это правило ещё не перенесено. Исправление границ не объявляется завершённым.
- Экспортируются первоисточники границ каждого H1-потока: `range_start_at`, `range_low_at`, `range_high_at`, `last_change_at`, `last_change_rule`, `range_origin`. Эти значения передаются на M1/M5 без изменения.
- Диагностика M1/M5 теперь включает в `h1_reference` полную историю H1 OHLCV, H1 состояний и события, чтобы установить точный момент расхождения без экспорта из TradingView.
- В панели показаны времена происхождения границ 0/1; добавлены отдельные тесты. Проверка 26/26 пройдена, а расчёты и синхронизация 0.2.0 сохраняются.

**Версия 0.2.1 — диагностическая, не подтверждённая на равенство TradingView. Использовать как торговый сигнал нельзя.**

## Изменения 0.2.0 — перенос закрытого H1 на M1/M5

- **Критическое исправление:** на M1 и M5 больше **не запускается собственный FlowEngine**. Потоки, уровни, IDM и события приходят только от отдельной истории **H1**.
- Из MOEX ISS часовые свечи H1 загружаются отдельно, с более длинной историей (до 3 000), чем M1/M5; это предотвращает короткий старт потока только от последних 14 дней.
- Исторические значения H1 становятся доступными **только после завершения соответствующей часовой свечи**. Для M5 час 20:00–21:00 доступен на закрытии свечи 20:55; для M1 — на закрытии свечи 20:59 (время Москва). На текущей открытой свече учитывается реальное время запроса, чтобы не подсматривать будущую часовую свечу.
- События правил №2–3 на M1/M5 отражаются однократно при закрытии H1, а не повторяются каждую минуту; индексы начала/архива потока переводятся в координаты младшего графика.
- Если H1 не загрузился, младший график продолжает показывать собственные структуру и FVG, но поток помечается **«ОЖИДАНИЕ / H1 недоступен»**, а не заменяется произвольным младшим потоком.
- Для **CSV M1/M5** добавлена кнопка **«Добавить H1 CSV»**, чтобы отдельно загрузить часовую историю того же инструмента. Без этого потоки на младшем CSV не рассчитываются. Совпадение тикера должен проверить пользователь.
- Экспорт JSON дополнен исходными OHLCV, источником H1 и временем закрытия использованной H1 свечи. Это позволит проверить отсутствие lookahead и сверить котировки.
- Воспроизведено расхождение по диагностикам AFKS от 10.11.2026: старая M5 показывала ШОРТ 8,539–8,918, а после корректного переноса H1 на M5 будет **ЛОНГ 7,989–9,306** на закрытии свечи 20:55 МСК. **Это тест внутренней синхронизации, НЕ доказательство совпадения с Pine.**
- Расширены автономные тесты: появление H1-потока только после закрытия часа, однократность событий, отсутствие lookahead, отсутствие ложного потока при недоступности H1.

**Не завершено:** перенос правила №1 и сверка №2/№3, структурной ломаной и FVG с TradingView 1:1. Параметры H1 по-прежнему предварительные. Версия 0.2.0 не предназначена для торговых решений и не выставляет заявки.

## Что уже работает

- Нативный оконный интерфейс Qt с интерактивным свечным графиком (колесо = масштаб, перетаскивание мышкой = прокрутка).
- Загрузка **исторических свечей MOEX ISS** для акций, например SBER/GAZP/IRAO (по умолчанию режим торгов TQBR). API публичный, но данные могут поступать с задержкой; это не поток котировок реального времени. По таймфреймам: M1, M5 (агрегация M1), H1, D1, W1, MN1.
- Импорт пользовательских CSV с Time/Open/High/Low/Close/(Volume), экспортированных из TradingView (также поддерживаются русские заголовки).
- Структурная ломаная: материнские, внутренние и цепочки внешних свечей; подтверждённые и формирующиеся плечи.
- FVG: трёхсвечная модель, отбрасывание гэпов по соседним теням, исключение внутренних свечей на M1/M5/H1, балансировка и пробой закрытием, цвет зоны и линия середины.
- Визуализация уровней 0/0,4/0,5/0,6/1 и предыдущего потока, событий предварительного движка №2–3, пары уровней IDM. На M1/M5 используется H1 (после закрытия часа).
- Дополнительные FVG H1/D1/W1/MN1 над младшим графиком (если источник данных доступен).
- Экспорт собственного состояния потоков/FVG в JSON для диагностики; встроены автономные тесты расчётного ядра.

## Что НЕ готово — важно

**Это тестовая сборка, а не подтверждённо совпадающая с TradingView рабочая версия.** Часть расчётного движка перенесена по исходнику, но полной 1:1 эквивалентности нет и сверка на пользовательском историческом экспорте не завершена.

- Условие потока №1 требует полного MTF-подтверждения и правильной отмены/восстановления событий старшей ликвидности — **не реализовано как достоверный сигнал**, поэтому не создаётся ложное событие «№1».
- №2 и №3 реализованы как **предварительная визуальная логика**, не прошли эталонную проверку на выбранном пользователем участке истории.
- Привязка новых FVG к сложным внешним импульсам и исторические уточнения структуры могут отличаться от Pine; библиотека хранит зоны, но не воспроизводит все оптимизации хранения и MTF-публикации из Pine.
- Обработка границ торговых сессий и свечей с High=Low требуется отдельно сверить по бирже. Автоматическое исключение нулевых свечей **не включено**: иначе можно скрытно поменять расчёты.
- На M1/M5 добавлена блокировка H1 до фактического завершения часа, но поведение живых диапазонов и остальные MTF-подтверждения ещё не гарантируют соответствия Pine. На FVG старших ТФ последняя исходная свеча исключается из проекции как потенциально незакрытая.
- Нет встроенного скринера, VWAP, BOS/CHOCH и MAX/MIN-рисования — таковы последние требования. В частности, MAX/MIN-пара остаётся **в расчёте IDM**, но не рисуется как отдельный блок.
- Никакие сделки или заявки приложение не выставляет. Не использовать предварительные сигналы для торговых решений без независимой проверки.

## Как конечному пользователю запустить готовую Windows-сборку

1. Получить архив **`FlowDesk-Windows-x64-Python-3.15.2`** из GitHub Actions (сборка описана ниже) или папку `dist/FlowDesk` от разработчика.
2. Распаковать целиком, **не извлекая один FlowDesk.exe без соседних файлов**.
3. Дважды щёлкнуть по `FlowDesk.exe`. **Python на компьютере пользователя не нужен.**
4. Программа откроется на явно помеченных синтетических DEMO-свечах. Для реальных данных нажать «Обновить MOEX», либо «Открыть CSV» и выбрать экспорт TradingView.

## Как получить EXE, если его пока нет

Файлы этого исходного проекта нельзя считать готовым `.exe`. PyInstaller **не кросс-компилятор**: Windows EXE собирается на Windows, а не в Linux-контейнере.

**Вариант без установки Python на ваш компьютер (GitHub Actions):** создать приватный GitHub-репозиторий, загрузить туда содержимое этого проекта с папкой `.github`, затем перейти `Actions` → `Build Windows FlowDesk exe` → `Run workflow`; в артефактах успешной сборки появится ZIP со всей папкой программы. Не загружайте приватный Pine-исходник в публичный репозиторий, если не хотите его раскрывать.

**Локальная сборка для разработчика:** установить Python 3.15.2 x64 на машине сборки и запустить `build_windows.bat` (виртуальное окружение, зависимости, тесты и сборка автоматизированы). Требовать установки Python от конечного пользователя не нужно.

## Проверка расчётов

```powershell
python -m unittest discover -s tests -v
```

Для эталонной сверки открыть один и тот же OHLCV в TradingView с `v2.04 H1 IDM fix` и в FlowDesk, вручную сопоставить до точного времени свечей: структура, начало и конец FVG, направление/начало/уровни потока и события №1–3. Файл `reference` нужен для достоверного переноса. Положительный результат модульных тестов — это **не** подтверждение совпадения сигналов с TradingView.

## Границы данных

- CSV без часового пояса читается в `Europe/Moscow` по умолчанию. Если экспорт в UTC, используйте ISO-дату с `Z` или Unix timestamp.
- ТФ файла определяется автоматически из шагов свечей, если распознаётся.
- MOEX ISS может отдавать историю с задержкой. Значения на незакрытых барах могут меняться.
- API зависит от режима торгов и типа инструмента; для другого рынка нужен отдельный адаптер.

## Исходные файлы

`flowdesk/market_data.py` — OHLCV/CSV/MOEX; `flowdesk/engine.py` — индикаторы; `flowdesk/gui.py` — Qt-график и боковая панель; `tests/` — автономные тесты; `reference/` — полный исходник Pine; `.github/workflows/build-windows.yml` — построение standalone EXE на Windows.
