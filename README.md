# FlowDesk for Windows - проверочная версия 0.2.23

## Изменения 0.2.23 — время начала свечи в основной подписи

- Из основной строки удалены «Получено HH:MM:SS» и безусловная подпись задержки 15 минут. Справа внизу показывается «Начало последней свечи» либо «Начало свечи под курсором», таймфрейм и биржевое начало OHLCV в МСК. Время запроса/получения и граница подтверждения остаются в диагностической подсказке источника.
- Чёрная метка перекрестия и строка справа используют общий формат времени Candle.time; добавлены ТФ и МСК. На пустом поле справа нет свечи — метка времени не подставляется от последней свечи. После обновления сохраняется подпись свечи под неподвижным курсором в историческом виде.
- Для M1 начало свечи 11:38 может совпадать с минутой получения 11:38:43. Само совпадение не означает подмену. Подтверждено чтением источников: HTTP использует begin, ISS+ — FROM, не received_at/published. В реальном прогоне 12.11 HTTP вернул M1 с началом 11:46 в 11:46:40, а DEMO позже передавал подтверждения свечей 11:33/11:34. Время OHLCV не сдвигается искусственно на 15 минут; индикаторная граница подтверждения не меняется.
- Qt-проверки отдельно различают свечу 11:23 и получение 11:38:43, а также случай реальной свечи 11:38; проверяется перекрестие, основная подпись и обновление при наведении.

## Изменения 0.2.22 — управление осями по двум видео

- Просмотрены обе записи: TradingView 39,666 с и FlowDesk 23,616 с. На фрагменте TradingView 14–18 с ценовая шкала растягивает график вокруг середины области, независимо от места нажатия. В FlowDesk этот центр теперь сохраняется; чувствительность снижена с 0,009 до 0,005 на пиксель по наблюдаемому движению.
- На фрагменте 23–26 с перетаскивание нижней шкалы вправо сжимает свечи, влево — расширяет, с фиксацией правого края. Направление исправлено. Масштаб зависит от расстояния до правого края вместо резкого экспоненциального множителя на каждый пиксель.
- Плавное перемещение, сохранение ширины свечей и ограниченное время закрытия процесса из 0.2.21 сохранены. Новые Qt-проверки проходят через настоящие события мыши: центр шкалы не зависит от точки захвата; обе оси независимы; исходные OHLCV не меняются; обратный жест восстанавливает диапазон.
- Направления и центры жестов сверены с видеозаписями. Полная идентичность всех скрытых настроек/чувствительности закрытого интерфейса TradingView не заявляется. Наблюдения: docs/chart_gestures.md.

## Изменения 0.2.21 — закрытие процесса и плавное перемещение

- Закрытие запрашивает отмену HTTP-загрузки между страницами/повторами, отменяет поток и обновление списка. Окно скрывается сразу. В основном процессе после явного закрытия запускается двухсекундный watchdog: зависший системный socket/DNS не удерживает приложение. Последний резерв завершает только собственный процесс через os._exit; SQLite публикуется транзакциями, список и настройки — атомарной заменой файла. Никакие чужие процессы не завершаются.
- Горизонтальная координата графика теперь дробная: перемещение на один пиксель работает без округления до целой свечи. Число слотов не зависит от пустого места справа, поэтому при движении не меняются ширина свечей и масштаб индикатора. Колесо сохраняет точку под курсором, нижняя шкала масштабируется относительно правого края. Положение сохраняется при приходе новых данных.
- Добавлены проверки выхода отдельных процессов при зависших HTTP/list/WebSocket/DNS и проверка готового Windows EXE через WM_CLOSE. Принудительный выход дополнительно проверяет откат незавершённой SQLite-транзакции.
- В 0.2.21 эти исправления подтверждались кодом и тестами; сверка жестов с двумя видео выполнена в 0.2.22 после отдельного согласия пользователя.

Не добавляются медь, RGBI/RGBIF, UCNY, мини-замены или иностранный список TradingView.

Для RFUD H4 используется физическое начало сессии; расписания до 2025 и полный паритет H4 с TradingView не подтверждены. Расчётные engine/liquidity/rule1 не изменены.

## Изменения 0.2.19 — автоматический поток MOEX ISS+ DEMO

- После первой загрузки MOEX режим «Авто» открывает один WebSocket/STOMP: `DEMO / guest / guest`, котировки `MXSE.securities` и готовые свечи `MXSE.candles` M1/H1/D1/W1/месяц (`m1`). Для TQBR; остальные режимы сохраняют HTTP-обновление раз в 60 секунд.
- Архив, восстановление после соединения/разрыва и резерв при недоступности потока — прежний MOEX ISS HTTP. При исправном потоке повторного минутного HTTP-опроса нет. Первое восстановление дополнительно загружает минутную историю для корректной текущей H1. Разрыв в свечах требует HTTP-перекрытия; нулевые свечи не создаются.
- Если публикации прекратились после закрытия торгов, за отложенной календарной границей H1/Д/Н/М выполняется свежий HTTP-запрос. Он позволяет подтвердить последний период без ожидания следующей сделки; часы компьютера сами по себе не подтверждают сохранённую свечу. Постоянные обновления потока не отодвигают этот контрольный таймер.
- Внутридневные свечи и котировки DEMO задержаны примерно на 15 минут по выполненной сетевой диагностике. Д/Н/М обновляются по другой схеме свежести. Их публикация и будущий TILL не подтверждают текущие свечи. Новая M1 обновляет формирующуюся H1; её подтверждение ждёт готовой H1 либо HTTP-восстановления. Расчётная граница сохраняется в кеше и не продвигается от часов компьютера или от котировки LAST.
- Котировка последней сделки, её время и статус торгов показаны отдельно от OHLC. Это не полная лента сделок. Заявки и стакан в этой версии не добавляются.
- Пауза, CSV и закрытие останавливают поток; смена тикера отбрасывает сообщения прежнего соединения. Переключение ТФ использует то же соединение. При разрыве — повторные подписки с увеличением интервала попыток; при отказе ресурса — HTTP без бесконечного цикла переподключений.
- Полностью сохранены отрисовка 0.2.18 (пустые только внутренние свечи, фитиль вне тела), перемещение X/Y и исходные модули расчётов структуры/FVG/IDM/потоков. Д — 00:00 МСК; Д/Н/М готовые от MOEX с аукционом, внутридневная фильтрация прежняя.
- Проверки: `python -m unittest discover -s tests -v`; отдельная реальная проверка `python tools/check_issplus_live.py` подписывается на SBER, принудительно разрывает TCP и проверяет повторное получение данных. Результаты сетевой проверки сохраняются в артефактах GitHub Actions, включая ошибки доступности сервиса.
- Сетевой тест использует отдельную короткую историю SBER из реального HTTP (полный архив проверяется отдельно). Ночной запуск без новых M1 отмечается `PARTIAL_NO_NEW_M1`: доступность подписок и восстановление проверены, появление новой минуты в этом запуске не подтверждено. Если после HTTP-восстановления сделки продолжались достаточно долго, отсутствие M1 считается ошибкой.

**Исходник в репозитории:** `reference/TradingView_Structure_FVG_VWAP_Screener_H1_v2.04_IDM_fix.pine` — историческая база v2.04. **Для текущего сравнения используется предоставленная диагностика TradingView v2.09**, поэтому полный паритет с действующей v2.09 пока не подтверждён.

**Платформа сборки:** Windows 10/11 x64, CPython **3.15.2 stable**, PySide6 Essentials **6.12.0 stable**, PyInstaller **6.22.3 stable**, tzdata **2026.4**. Версии зависимостей закреплены для воспроизводимости.

## Изменения 0.2.18 — фитили вне тела и свободное перемещение графика

- **У внутренних пустотелых свечей больше нет вертикальной линии внутри тела:** верхний фитиль заканчивается на верхнем крае прямоугольника, нижний начинается под его нижним краем. При этом сохранены все OHLCV, тип свечи и цвет контура. Раздельные фитили используются и для остальных свечей, как в TradingView.
- **Перетаскивание самого графика работает одновременно по двум осям**, как на представленном видео TradingView: горизонтально движется история свечей, вертикально перемещается вся шкала цен и привязанные к ней FVG, уровни и структура. Вертикальный масштаб во время панорамирования фиксируется: размер свечей и диапазон шкалы не скачут при появлении старой истории.
- Перетаскивание **нижней временной оси** по-прежнему меняет масштаб X, а **правой ценовой оси** — масштаб Y. Колёсико и End/F/0 работают как ранее; двойной щелчок по ценовой оси включает автоматическую шкалу.
- Параметры свечей, стратегия расчёта структуры/IDM/FVG, потоки №1–3, M1/H1/D/W/M, MOEX HTTP/ISS и кеш **не менялись**.
- Дополнительные Qt-тесты проверяют прозрачный центральный пиксель внутренних свечей и одновременное перемещение графика по X/Y без изменения вертикального масштаба.

## Изменения 0.2.17 — корректная пустотелость внутренних свечей

- Исправлена ошибка 0.2.16: пустыми **больше не делаются все восходящие свечи**.
- **Внутренней** считается свеча, у которой `High <= High` текущей **материнской** свечи и `Low >= Low` материнской. Вложенные внутренние свечи не заменяют материнскую; равенство границ допускается. Соответствует существующей high/low-логике FVG и описанию структуры Pine.
- Внутренние свечи показываются **пустотелыми при любом направлении Close относительно Open**: контур виден, середина прозрачна и показывает фон/FVG.
- **Обычные** (не внутренние) свечи: восходящие сплошные белые, нисходящие сплошные чёрные. Фитили остаются тонкими.
- Это **только визуальная классификация**, рассчитываемая при загрузке свечей; собственно алгоритмы структуры, FVG, IDM, правил потоков и исходные OHLCV не изменены.
- Дополнительные тесты проверяют последовательные вложенные материнские свечи, равенство границ и фактические пиксели Qt-отрисовки белых, чёрных и пустотелых тел.

## Изменения 0.2.14 — автоматическое обновление с задержкой

- После открытия инструмента MOEX включено **«Авто · 60 с»**: через минуту после завершения запроса терминал сам догружает свежий диапазон, обновляет свечи и расчёты. Подписка и постоянное соединение не используются: терминал выполняет обычные HTTP-запросы ISS. Флажок позволяет поставить обновление на паузу; ручная кнопка сохранена.
- Автообновление относится только к открытому инструменту/режиму/таймфрейму MOEX. На DEMO и CSV таймер остановлен. Незавершённый ввод нового тикера не открывается автоматически; если ввод начат во время автозагрузки, он сохраняется. Запросы выполняются последовательно, во время загрузки повторный таймер не создаёт очередь. При закрытии окна таймер остановлен.
- При ошибке автозагрузки прежний согласованный снимок остаётся на экране, ошибка показана в строке состояния; модальное окно каждую минуту не появляется. Следующая попытка запланирована автоматически. Историческое положение и масштаб графика сохраняются; открытый у правого края график следует за последними свечами.
- Для публичного ISS применяется консервативная задержка **15 минут**, указанная в [описании MOEX](https://www.moex.com/a7939). Граница расчёта закрытых свечей — время начала запроса минус 15 минут, а не часы компьютера. Например, в 12:05 H1 11:00–12:00 ещё не считается закрытым. Это настройка ожидаемой задержки источника, а не измерение фактического лага; она не устраняет возможные задержки связи. Старые снимки, рассчитанные по времени запроса, ограничиваются консервативно без повторной загрузки архива.

## Изменения 0.2.6 — исключение аукциона открытия **на всех таймфреймах**

- **Единое правило источника:** аукционные свечи открытия удаляются **до** структуры, IDM, FVG, потоков и теневого №1. После удаления трёхсвечные FVG строятся по последовательным **оставшимся** свечам; искусственные свечи и ценовые уровни не подставляются.

Цена аукциона закрытия, если она входит в обычный торговый час, этим способом ещё не удаляется: для полной внутрисвечной очистки необходим минутный источник.

## Что уже работает

- Нативный оконный интерфейс Qt с интерактивным свечным графиком (колесо = масштаб, перетаскивание мышкой = прокрутка).
- Загрузка **исторических свечей MOEX ISS** для акций, например SBER/GAZP/IRAO (по умолчанию режим торгов TQBR). API публичный, но данные могут поступать с задержкой; это не поток котировок реального времени. По таймфреймам: M1, M5 (агрегация M1), H1, D1, W1, MN1.
- Импорт пользовательских CSV с Time/Open/High/Low/Close/(Volume), экспортированных из TradingView (также поддерживаются русские заголовки).
- Структурная ломаная: материнские, внутренние и цепочки внешних свечей; подтверждённые и формирующиеся плечи.
- FVG: трёхсвечная модель, отбрасывание гэпов по соседним теням, исключение внутренних свечей на M1/M5/H1, балансировка и пробой закрытием, цвет зоны и линия середины.
- Визуализация уровней 0/0,4/0,5/0,6/1 и предыдущего потока, событий предварительного движка №2–3, пары уровней IDM. На M1/M5 используется H1 (после закрытия часа).
- Дополнительные FVG H1/D1/W1/MN1 над младшим графиком (если источник данных доступен).
- Экспорт собственного состояния потоков/FVG в JSON для диагностики; встроены автономные тесты расчётного ядра.

## Что НЕ готово — важно

**Это тестовая сборка, а не подтверждённо совпадающая с TradingView рабочая версия.** Часть расчётного движка перенесена по исходнику, но полной 1:1 эквивалентности нет и сверка на пользовательском историческом экспорте не завершена.

- Условие потока №1 требует полного MTF-подтверждения и правильной отмены/восстановления событий старшей ликвидности — **не реализовано как достоверный сигнал**, поэтому не создаётся ложное событие «№1».
- №2 и №3 реализованы как **предварительная визуальная логика**, не прошли эталонную проверку на выбранном пользователем участке истории.
- Привязка новых FVG к сложным внешним импульсам и исторические уточнения структуры могут отличаться от Pine; библиотека хранит зоны, но не воспроизводит все оптимизации хранения и MTF-публикации из Pine.
- Обработка границ торговых сессий и свечей с High=Low требуется отдельно сверить по бирже. Автоматическое исключение нулевых свечей **не включено**: иначе можно скрытно поменять расчёты.
- На всех ТФ поток подтверждается по времени закрытия исходной свечи, но полное поведение живых диапазонов и остальные MTF-подтверждения ещё не гарантируют соответствия Pine. Для FVG старших ТФ используется отдельное состояние только по закрытым источникам.
- Нет встроенного скринера, VWAP, BOS/CHOCH и MAX/MIN-рисования — таковы последние требования. В частности, MAX/MIN-пара остаётся **в расчёте IDM**, но не рисуется как отдельный блок.
- Никакие сделки или заявки приложение не выставляет. Не использовать предварительные сигналы для торговых решений без независимой проверки.

## Как конечному пользователю запустить готовую Windows-сборку

1. Скачать ZIP **`FlowDesk-0.2.23-Windows-x64`** по ссылке на готовую сборку или получить папку `dist/FlowDesk`.
2. Распаковать целиком, **не извлекая один FlowDesk.exe без соседних файлов**.
3. Дважды щёлкнуть по `FlowDesk.exe`. **Python на компьютере пользователя не нужен.**
4. При запуске автоматически загрузится последний инструмент и ТФ, при первом запуске — SBER H1. Выберите другой инструмент справа или введите тикер и нажмите Enter. Для собственного экспорта TradingView используйте «Открыть CSV».

## Как получить EXE, если его пока нет

Файлы этого исходного проекта нельзя считать готовым `.exe`. PyInstaller **не кросс-компилятор**: Windows EXE собирается на Windows, а не в Linux-контейнере.

**Вариант без установки Python на ваш компьютер (GitHub Actions):** создать приватный GitHub-репозиторий, загрузить туда содержимое этого проекта с папкой `.github`, затем перейти `Actions` → `Build Windows FlowDesk exe` → `Run workflow`; в артефактах успешной сборки появится ZIP со всей папкой программы. Не загружайте приватный Pine-исходник в публичный репозиторий, если не хотите его раскрывать.

**Локальная сборка для разработчика:** установить Python 3.15.2 x64 на машине сборки и запустить `build_windows.bat` (виртуальное окружение, зависимости, тесты и сборка автоматизированы). Требовать установки Python от конечного пользователя не нужно.

## Границы данных

- CSV без часового пояса читается в `Europe/Moscow` по умолчанию. Если экспорт в UTC, используйте ISO-дату с `Z` или Unix timestamp.
- ТФ файла определяется автоматически из шагов свечей, если распознаётся.
- MOEX ISS может отдавать историю с задержкой. Значения на незакрытых барах могут меняться.
- API зависит от режима торгов и типа инструмента; для другого рынка нужен отдельный адаптер.

`flowdesk/market_data.py` — OHLCV/CSV/MOEX; `flowdesk/engine.py` — индикаторы; `flowdesk/gui.py` — Qt-график и боковая панель; `tests/` — автономные тесты; `reference/` — полный исходник Pine; `.github/workflows/build-windows.yml` — построение standalone EXE на Windows.
